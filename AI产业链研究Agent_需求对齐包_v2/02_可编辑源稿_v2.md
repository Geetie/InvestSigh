# AI产业链研究Agent方法论与产品需求

需求对齐稿 v2　2026年9月14日

本文供需求方与实现方共同确定产品范围、研究逻辑、系统行为与验收标准。目标是构建一个每天持续研究 AI 产业链、能够在具体时点给出股票买卖建议的 Agent。第一批从 NVIDIA 及其核心产业链开始，第一版使用公开信息。

本文区分三类内容：第二章列出讨论中已确认的投资规则；其余章节将这些规则转化为建议的产品设计与验收要求；第十一章列出仍需确定的实施参数。AGIX 是基于需求方现有持仓提出的主基准工作候选，尚待本需求文档确认。

本文替代此前未定稿的 v1 需求草稿。已有 HTML 图谱和 NVIDIA 样例是原型输入；本文件不表示数据服务已经接通、自动研究已经运行，或投资效果已经得到验证。

阅读顺序：第一至三章明确目标、投资原则和首批范围；第四至七章定义研究方法与股票判断；第八至十章定义产品运行和验收；第十一章及附录供实现方拆解工作与确认参数。

## 一 产品目标与核心闭环

### 产品要解决的问题

公司资料、市场观点和股价分散在不同地方，单条信息很难自动关联到已有判断和其他公司。产品需要持续回答：发生了什么新变化，改变了谁的赚钱能力，价格已经反映了多少，现在值得买入或卖出什么，以及什么证据会让这个判断改变。

研究以产业链组织，以公司为独立判断对象。公司价值与股票价格分开研究：价值层面聚焦增长动力、增长确定性和护城河；价格层面理解外部预期、价格隐含假设和 Agent 独立判断之间的差异。最终将两者连接到同一投资期限下的预期收益与基准比较。

### 从信息到行动的流程

公开信息进入 → 追源去重与核验 → 更新公司及产业关系 → 修订增长和护城河判断 → 更新财务与估值假设 → 比较个股与基准预期收益 → 发布股票建议 → 持续验证与留存历史。

每天维护判断不等于每天必须产生新买卖信号。系统可以维持原判断，也可以明确表示研究尚未完成。任何结论应能追溯到证据、假设、计算和上一版本；任何缺口应能转为后续研究任务。

### 首版的成功定义

先验证一条关于 NVIDIA 的真实信息能否推动完整研究流程：发现受影响公司，逐步解释经济传导，更新各公司的价值与价格判断，并分别给出有依据的股票建议。短期验收研究深度、数据质量和系统行为；投资效果在对应周期内另行检验。

## 二 已确认的投资规则

本章是实现时应遵守的策略约定。技术实现、信息筛选和页面设计不得悄悄增设与这些约定冲突的买卖条件。

| 项目 | 已确认规则 |
| --- | --- |
| 主周期 | 一个季度到一年；每条建议明确具体期限和起算时点 |
| 机会类型 | A 类为基本面改善且价格尚未充分反映；B 类为基本面未明显恶化但价格变得有吸引力；两类均覆盖 |
| 决策对象 | 针对股票给建议；第一版不做个人组合仓位分配 |
| 增长阶段 | 尚未兑现增长与已兑现增长的公司都可进入买入建议，分别检验兑现路径和持续性 |
| 护城河 | 影响判断的维度，不是买入的必要条件；周期和供需机会也可研究、推荐 |
| 提前判断 | 允许经营结果完全兑现之前提出买入建议，必须说明假设、证据缺口和验证条件 |
| 官方确认 | 不是必要条件；可信、独立、可复核的第三方证据可以支持独立判断 |
| 买入标准 | 有依据预计绝对收益为正，并且高于同一期间的主基准收益 |
| 超额收益门槛 | 不设最低幅度；不能额外要求超额收益达到固定百分比或覆盖某个安全边际才允许买入 |
| 卖出标准 | 有依据预计无法继续跑赢基准，就建议卖出，即使仍有正的预期绝对收益 |
| 价格下跌 | 先触发强制复查，不设置价格止损；也不因下跌自动判定低估 |
| 催化剂 | 明确催化剂不是买入必要条件；低估本身可构成理由，仍需解释兑现可能性与复查期限 |
| 更新方式 | 每日固定更新，加重大事件触发的临时研究与复查 |
| 信息范围 | 第一版先使用公开信息 |

### 判断中的几个必要区分

有依据预计跑不赢，与暂时无法判断能否跑赢，是两种状态。前者适用卖出规则；后者应显示缺口并复查，不能自动变成卖出。预测的不确定性和下行情景必须展示，但不另设用户未同意的固定置信度门槛。

护城河较弱与护城河正在减弱分开记录。增长机会扩大与增长兑现更确定也分开记录。不同状态可以同时出现，例如增长动力增强、增长确定性减弱、护城河不变。

每次复查重新评估既有假设，不通过不断延长期限掩盖预测未兑现。卖出建议表示股票层面的退出判断，不代表系统知道用户实际持仓，也不自动转为做空建议。

## 三 覆盖范围与基准

### 第一批研究对象

已确认第一批为 NVIDIA 及其核心产业链，按可核实的关系确定名单，不按预设公司数量凑名单。首批分为 NVIDIA 本身、直接上游供应商、下游客户与合作伙伴、重要竞争与替代者。

每家公司都需完成独立研究，回答其增长、护城河、价格和投资吸引力。NVIDIA 是研究入口，最终更值得研究或买入的对象也可能是供应商、客户或竞争者。

关系应落实到具体产品、服务、合作阶段和有效期间。已经完成的历史合作不能直接当成当前采购；同一家公司的不同产品可以有不同供应商和不同竞争关系。首批正式名单由一轮关系核验产生，附原始出处和纳入理由。

### 全景图与深度研究分开维护

保留现有从能源到应用的整体位置图，逐步扩展版图。现有本地文件包含 44 个公司或机构节点，清单见附录一；这不等于首版对全部节点完成深研或提供同样频率的扫描。

建议每个节点展示研究深度：位置收录、关系已核验、研究基线完成、持续跟踪。研究未完成要明确显示，不能包装成中性评级或没有投资机会。首版新增数据和研究资源优先投入 NVIDIA 核心生态及受重要事件影响的对象。

公司与证券分开管理。未上市机构可以进入产业研究；股票建议必须映射到核实过的具体证券、上市地、币种与交易时段。全球关键公司保留研究覆盖，非美证券是否进入首版推荐范围在实施参数中确定。

### 环境层与本版边界

保留轻量环境研究，包括利率与折现要求、融资条件、AI 投入及需求周期、能源与交付约束、重要政策变化。环境变化进入公司和基准研究，不另建黄金、BTC 或跨资产配置模块。

第一版交付到研究与股票建议。组合权重优化、个人账户管理和交易执行不纳入首版；系统也不以缺少真实持仓为由阻止独立个股研究。

### 主基准工作候选

已确认采用 ETF 作为主要比较对象，同行比较作为辅助分析。建议采用需求方已持有的 AGIX。具体代码在需求文档确认时冻结；下文以 AGIX 为工作假设。

AGIX 官方资料将其定位为覆盖 AI 硬件、基础设施和应用的基金，并持有部分非上市公司资产。因此它适合表达“选股相对继续持有这一 AI 投资选项是否创造价值”，不等于所有 AI 上市公司的纯行业平均表现。研究与复盘需使用基金本身的收益，而非用其公开股票指数替代整个基金。[1][2]

建议统一使用相同起止时间、美元口径、包含分红再投资的市场价格总回报。净值收益可作诊断；基金费用已体现在基金实际回报中，不能再次重复扣除。基准不因建议表现好坏而更换，未来如变更，必须记录生效日期并保留旧口径结果。

## 四 公司价值研究与深度标准

### 增长动力与赚钱机制

研究底稿应讲清公司靠什么产品或服务赚钱，谁付费，采购或使用如何转化为收入，主要成本和资本投入是什么。进一步解释增长来自需求扩张、份额、价格、产品组合、单位用量、渗透率还是新业务，以及每个驱动能持续多久。

为主要业务维护少量关键驱动与财务连接。硬件区分订单、排产、出货、验收、收入和回款；云业务区分签约、通电、上线、利用率与收费；软件区分使用、付费、续约、留存与增购。不同商业模式使用不同指标。

增长需要连接到利润、现金流和每股价值。收入增长可能同时需要降价、增加资本开支、库存、应收或融资。模型要能解释经营增长、利润率、再投资、净负债和股本变化如何影响股东价值，不以收入增速直接代替投资回报。

### 增长确定性

对每个驱动标明哪些已经发生，哪些属于计划、指引或预测，哪些还依赖客户预算、供应认证、产能、能源、交付、商业化或竞争条件。将兑现时间与判断置信程度分开记录。

尚未盈利的公司可以研究和推荐，但要解释商业模式、兑现路径及资金需求；已经盈利的公司重点检验利润和现金流的持续性。经营事实可信，不等于未来增长必然兑现。

### 护城河与竞争

护城河研究要解释优势机制，以及它保护的是份额、定价、成本、客户留存、资本回报还是创新效率。比较真实替代方案、客户切换条件和跨产品代际的竞争能力。

产品一时领先、供给紧缺或高毛利都可以成为研究证据，但不能单凭其中一项直接认定长期护城河。需要区分持续竞争优势、产品周期、供需周期与经营效率改善。

### 完整研究基线应交付什么

| 内容 | 深度要求 |
| --- | --- |
| 业务与产业位置 | 产品、客户、收入来源、成本与资本需求；主要产业关系落实到具体合作内容 |
| 增长驱动 | 关键变量、历史基线、未来假设、规模、期限和财务落点 |
| 增长确定性 | 兑现阶段、关键依赖、支持证据、反证、可能失败的原因 |
| 护城河 | 优势机制、可替代性、竞争比较、维持优势所需投入及失效条件 |
| 财务与估值 | 公开历史数据、预测底稿、假设、计算过程、敏感性和每股口径 |
| 价格与行动 | 外部预期、价格隐含假设、独立判断、与基准比较及股票建议 |

这是一份有内容的研究底稿，不是六个空标题。主要结论需要原始材料定位、期间、单位和推导；材料不足时记录缺口，不用模板化文字冒充完成研究。

### 增量更新协议

每次更新记录旧判断、新信息、新判断、影响期间、支持证据与反证。增长动力、增长确定性和护城河分别标为增强、减弱、不变或待判断，并用文字解释原因。没有新增信息时不制造状态变化。

## 五 价格与市场预期研究

### 先理解当前价格需要什么条件成立

“先假设市场是对的”转化为一个反向检验：哪些增长、利润、再投资、风险和持续时间的假设，可以使当前价格成立？价格不是市场共识的唯一解，反推结果应展示假设组合、区间和替代解释。

建议保存三份相互区分的判断：公开可观察的外部预期，特定估值假设下的价格隐含要求，以及 Agent 根据业务证据形成的独立判断。公司指引、券商公开预测和社交讨论继续保留各自身份，不能合并成没有来源的“市场认为”。

### 公开信息条件下的预期研究

第一版可使用公司指引、公开分析师预测、财报评论和可访问的研究摘要。若只有少量机构的公开数据，只能称公开预测样本，显示样本数、来源和期间，不能标成完整一致预期。

KOL 讨论可用于识别叙事、分歧和待核验线索；热度不等于市场全体共识。缺少付费一致预期数据库时，仍可进行反向估值与独立研究，但必须披露覆盖缺口。

### 财务预测与估值

估值方法按商业模式选择，例如正常化利润和现金流、包含再投资的现金流估值、分部估值及适当的同行比较。每个价格区间都要能追溯到经营预测、估值参数、股本和计算日期。

先完成经营假设再计算价值，不能为得到买入或卖出结论倒填参数。估值中的事实输入、模型估计和人工设定分别保存。上下行情景用于说明不确定性，不把宽泛区间包装成精确预测，也不默认编造情景概率。

### AGIX 也需要前瞻研究

比较未来表现要求同时研究个股和基准。建议为 AGIX 建立共用的简化底稿，跟踪公开持仓、主要业务暴露、增长及估值变化和环境情景，形成同一期限下有解释的收益判断。

公开持仓缺口、非上市资产估值和无法独立核验的预测要单列假设与敏感性。不能拿 AGIX 过去半年的涨幅充当未来半年预期，也不能忽略基金中没有建模的部分而声称完成了整个基金的预测。

用于决策的收益预测必须采用一致的情景与期间口径。首版具体采用中性情景还是有依据的概率加权结果，需通过样例确定并记录方法版本；不能比较个股乐观情景与基准悲观情景。

### 每日价格变化如何解释

先检查行情时间、交易时段、币种、复权和公司行动，再对照基准、同行、公司事件和环境因素寻找解释。已确认解释、合理推断与无法解释的部分分别显示。

股价上涨不自动证明护城河增强，下跌不自动证明基本面恶化。即使减去基准变化，剩余波动也不能直接归因于某条消息。异常下跌触发复查；复查未完成时显示状态和原判断时间。

## 六 公开信息与证据筛选

### 第一版信息边界

第一版使用公开可访问的信息，不依赖新增付费研报库、专家网络或付费市场预期数据库。公司 IR、监管披露、官方财报材料和公开问答构成研究基础；公开产品材料、第三方研究、媒体、X、YouTube 和 Substack 用于补充。

公开可阅读不等于可以稳定批量抓取。每个来源应记录访问方式、更新时间、可提取字段、采集限制和失败处理。尊重登录、付费和访问限制；遇到不可访问正文，只能引用实际取得的内容，不能声称读过全文。

公开数据不等于零运行成本。模型调用、搜索、存储和部署费用另行估算；本次讨论未授权新增付费数据订阅。

### 信息分级的操作定义

| 层级 | 内容 | 处理方式 |
| --- | --- | --- |
| 一手 | 公司和监管披露、官方财报、IR 演示、问答、产品公告 | 优先分析；继续区分已发生事实、前瞻指引与营销性主张 |
| 1.5 手 | 券商公开研究、专业第三方调查、媒体采访及非正式公开沟通 | 分开提取原始调查、引用、估计和观点，核实方法与身份 |
| 二三手 | KOL 观点、社交平台讨论、视频和公开文章 | 检查证据、新增信息、反证及叙事价值，不按粉丝量定权重 |

上表为建议的执行定义。来源分级不按系统自行判断的“法律责任”划分，也不只按平台划分。公司在社交平台发布的原始公告仍属于公司来源；KOL 引用财报时，相关事实回到原财报；专业人士可复现实测也可能提供有价值的独立证据。

### 从信息到可用主张

1. 保存原始出处、作者、发布时间、事件时间、首次获得时间与版本，记录页码、段落或视频时间点。
2. 拆成具体主张，识别公司、产品、指标、期间、单位及其属于事实、计划、预测还是解释。
3. 追踪来源并去重；多个账号转述同一消息只增加传播记录，不增加独立证据数量。
4. 判断证据质量，包括是否直接知情、方法可复核性、口径匹配、独立佐证、相反证据和利益关系。
5. 判断研究增量：具体改变哪个增长驱动、兑现条件、护城河或价格预期。重复但无增量的信息归档。
6. 对重要且不确定的主张优先核验，寻找替代解释和反证；时间或计算预算到限时保留待核验任务。
7. 将主张标为有支持、有争议、待核验、被否定或被新版本替代，再更新依赖它的结论。

来源分级决定先看什么，证据质量决定相信多少，经济重要性决定研究多深。首版不预设一手与 KOL 的固定分数加权，更不能用文章数量或情绪强度投票决定买卖。

允许可信、独立、可复核的第三方证据进入判断。官方确认不是硬门槛，但事实可信度、模型推断可信度和未来经营兑现确定性必须分开。原始证据被纠正或撤回时，所有依赖结论都应进入复查。

### 公开数据的缺失处理

| 缺失情形 | 规定行为 |
| --- | --- |
| 没有订单金额或供应份额 | 明示未披露；可分析机制和范围，不填入猜测的事实数值 |
| 只有研报摘要或少量公开预测 | 标明取得范围和样本，不声称完整研报或完整一致预期 |
| 视频无可用字幕或全文 | 显示尚未完成解析，保留任务及公开入口 |
| 只有延迟行情 | 显示行情时间与延迟；不标实时，不伪装为当前可成交报价 |
| 关键材料或估值输入缺失 | 保留已完成研究，明确不足以完成哪一步；必要时输出待判断 |

## 七 产业链传导与股票建议

### 关系需要保存的内容

公司、业务和产品分别建模。关系类型包括供应采购、制造封装、产品采用、授权、渠道、合作验证、竞争替代、互补及投资关系。产品流、资金流和需求信号分别表示。

每条关系记录两端对象、具体产品或服务、合作阶段、有效时间、证据和已知经济暴露。订单、采购承诺、资本开支、排产与收入不能直接等同；金额或份额未披露就保留未知。

### 传导的研究边界

先研究事件当事公司与直接关系，再沿经济重要且有依据的路径继续研究，不机械限制只能一层，也不把所有 AI 公司联动标成同一方向。每一步说明影响变量、方向、幅度或范围、成立条件、反向力量和体现时间。

例如，云厂商提高资本开支后，先确认投入类别和供应商，再分析采购、交付、产能及利润影响。追踪到具体电力公司时，需要地点、供电方式或采购关系等依据，不能从 GPU 需求增加直接推导所有能源公司受益。这个示例描述研究方法，不是当前订单事实。

页面默认呈现与当前公司紧密相关的局部关系，需要时展开完整路径。循环路径、同一终端需求和重复证据要去重，避免在多层传导中反复放大同一个冲击。

### 建议状态与决策规则

| 条件 | 股票层面的输出 |
| --- | --- |
| 预期绝对收益为正且高于同期主基准 | 可给出买入建议，列明依据、期限和假设；不另设最低超额收益幅度 |
| 有依据预计无法继续跑赢基准 | 建议卖出；不因仍有正收益而自动保留原买入判断 |
| 暂时无法判断是否跑赢 | 待判断或复查中，说明缺口；不能等同于卖出 |
| 新材料没有改变投资判断 | 维持原判断并记录本次核查，不制造新信号 |
| 单纯价格明显下跌 | 强制复查后重新判断；不自动止损，也不自动抄底 |

只有已完成相应研究并具备可解释预测时，才能应用收益比较规则。对没有完成模型的公司，不能因为随意填入一个略高于基准的数字就生成买入建议。

预期绝对收益为负、但仍可能跑赢基准时，已确认不能新增买入；对已有积极建议是否立即转为卖出尚未单独约定。本版先列为需要复查的边界情形，待完整样例校准，不隐含新增规则。

### 一条建议必须交付的内容

| 字段 | 要求 |
| --- | --- |
| 标的与时点 | 公司、具体证券、币种、参考价格、行情时间、建议发布时间和生效假设 |
| 行动 | 买入、卖出、待判断或维持原判断；说明适用情形，不编造实际持仓数量 |
| 判断期限 | 一个季度到一年中的具体期限、起算点、复查日期 |
| 变化原因 | 新信息及相对上一版本改变的事实、假设和结论 |
| 价值与价格 | 增长、确定性、护城河、外部预期、价格隐含假设和独立估值 |
| 收益比较 | 个股与基准同期收益预测、计算底稿、方法、敏感性和数据缺口 |
| 传导与时点 | 哪些相关公司受影响、条件、时滞及为何现在形成建议 |
| 验证与反证 | 支持和反对证据、未兑现条件、可能推翻判断的事件和到期复查 |

明确催化剂若存在则记录；不存在时说明价值可能被认识的路径和时间不确定性。每家公司独立判断，供应商与 NVIDIA 有关系本身不构成买入依据。

## 八 产品入口与每日运行

### 三个阅读入口

产业图谱保留能源到应用的位置全景，显示研究深度、更新时间和变化标记。点击公司查看局部关系；选择事件可查看有证据的传导路径及成立条件。

公司研究页首先展示产业位置、增长动力、增长确定性、护城河、当前建议和本次变化。展开后查看完整底稿、原始证据、财务与估值、反证及历史版本。结论简洁，研究内容保持深度。

每日研究页展示重要信息、受影响公司、建议变化和下一验证节点。未完成核验、数据失效和研究任务失败均可见。通知渠道及通知聚合方式另定，不通过通知过滤偷偷改变投资规则。

### 提问必须成为实际研究任务

从公司、产品或关系提出的问题，继承所选对象、当前页面和研究基线，进入与自动监测相同的研究流程。用户应看到排队、研究中、待补证、已完成或失败状态，以及答案、证据和产生的更新。

回答要说明是否改变已有结论，以及哪些事实、关系或假设被加入研究库。仅将问题保存到本地文本或浏览器存储，不算已经开展研究。

### 每日固定更新与事件触发

固定更新检查首批深研公司的价格、公开材料和关键变量，维持可复查的研究基线。建议以美股收盘后为主更新窗口，具体时刻、时区和非交易日安排由实现方确认。

重大事件触发额外研究，包括财报与指引、重要订单和产能、产品与竞争变化、关键证据撤回，以及异常价格变化。触发标准是研究优先级规则，不是价格止损或最低超额收益门槛。

事件发现时间、入队时间、研究完成时间和发布结果时间分别记录。先显示发现事件或正在复查，完成分析后更新判断；不能把尚未研究的事件包装成已验证结论。

建议默认自动更新研究与图谱，并保留可审查版本。新增关系和重大建议变化也必须满足同样的证据与字段要求；有争议的推断以推断状态发布。此处为产品默认方案，精确的发布与人工复核政策随需求文档确认，不预设每次更新必须人工批准。

### 增量计算与失败降级

每日运行共用一套采集、核验、传导、估值、决策和发布流程。只重算受到新信息或价格变化影响的对象，聚合同一事件的连续报道，避免无变化公司每天重复生成长报告。

采集失败、接口限流、模型超时或行情过期时，保留上次有效结果并清楚显示日期和失效状态；不覆盖为无意义空值，也不把旧数据标为最新。任务允许重试，重复执行不得重复生成事件或建议。

前端以稳定布局和按需加载保证流畅，不持续运行不必要的全图动画和全图模拟。公开数据的更新频率决定可承诺的时效，事件触发不代表毫秒级响应。

## 九 数据与实现约束

### 持久保存的对象

| 对象 | 必须保存的信息 |
| --- | --- |
| 公司与证券 | 稳定标识、多业务位置、具体证券、币种、财年和研究深度 |
| 产品与关系 | 类型、双方、产品代际、合作阶段、有效期、经济暴露和证据 |
| 来源与主张 | 原始内容或合法保留的片段、定位、作者、版本、时间、引用链和主张性质 |
| 事件与影响 | 去重身份、当事公司、关联对象、影响变量、条件、时滞和反证 |
| 研究基线 | 经营机制、历史数据、驱动模型、价值状态和结论版本 |
| 价格与预期 | 行情快照、外部预测样本、反向估值、独立模型及缺口 |
| 基准与建议 | 基准身份及研究底稿、收益口径、建议、期限、规则版本和引用的证据版本 |
| 任务与复盘 | 状态、输入输出、运行成本、失败原因、复查节点、评估结果和修改记录 |

发生时间、公开时间、系统首次获得时间、分析时间与判断生效时间分开。事后补入历史资料仍记录补入时间；预测修订、财务重述和原文更正以新版本保存，不覆盖过去可见的版本。

### 技术实现的边界

网页或文档中的外部文字作为研究数据处理，不得改变系统指令或策略规则。关键数值保留原表、单位、期间、币种和计算路径；计算与口径检查由可测试的程序完成，不依靠模型口算。

正式研究库与 HTML 展示分离。数据应可导出、迁移和恢复；不能将唯一研究记录放在单个浏览器的本地存储中。分享给同事时应显示资料日期和版本；公开信息输入不自动授权公开发布整个研究库。

首版先明确模块输入输出，可由一个或多个 Agent 实现；不要求先搭复杂的多 Agent 网络或某一种图数据库。实现方需要提供运行、部署、故障定位、数据备份与费用记录方案。

### 数据来源登记

每个来源登记公开入口、实际可获得内容、抓取方式、可预期延迟、更新频率、访问限制及备选来源。行情记录分红、拆股等公司行动处理方式。来源质量和作者表现可逐步按专业领域积累，但不能用模型自评替代人工核验样本。

## 十 验收与持续复盘

### 一条真实事件的完成标准

实现方应交付六个可连续追溯的结果：发生了什么新变化，改变公司的什么，影响怎样传导，价格反映多少，当前建议是什么，后续怎样验证。事件研究应同时展示原基线和新结果。

先用 NVIDIA 完整研究建立深度标准，再选择涉及供应商、客户或竞争者的真实事件验证多公司传导。研究样例中不得把未披露订单量、份额或采购金额填成已确认数据。首批名单和样本事件完成核验后作为验收输入固定下来。

### 必测反例

| 编号 | 场景 | 预期行为 |
| --- | --- | --- |
| T01 | 十篇文章转述同一匿名订单消息 | 保留一个原始证据来源及传播记录，不提升为十份独立佐证 |
| T02 | 只有一份公开盈利预测发生变化 | 更新公开样本；不声称完整市场一致预期已改变 |
| T03 | 官方仅披露验证完成 | 不自动升级为量产供应、确认订单或收入 |
| T04 | 第三方证据可信且可复核，官方尚未确认 | 可以纳入独立判断，标出假设及验证条件，不因缺官方确认一票否决 |
| T05 | 基本面改善但价格已经更充分反映 | 分开更新价值状态与投资判断，不机械产生买入 |
| T06 | 预期绝对收益为正，且仅略高于基准 | 不因额外安全边际、固定置信度或最低超额幅度门槛拒绝建议 |
| T07 | 预期仍有正收益，但预计跑不赢基准 | 形成卖出建议并解释相对判断变化 |
| T08 | 股价大跌且原因未明 | 触发强制复查；不自动止损、不自动买入，也不擅自修改护城河 |
| T09 | 低估但缺少明确催化剂，或公司护城河不强 | 分析兑现可能性、周期与风险；不把这两项设为硬性买入门槛 |
| T10 | 模型暂时不能判断相对收益 | 输出待判断和缺口；不混同为预计跑不赢 |
| T11 | 盘后消息进入或发生拆股分红 | 不使用消息前报价假设可成交；收益计算正确处理时间和公司行动 |
| T12 | 原证据被撤回或财务数值重述 | 追踪依赖关系、触发复查，保留前后版本及当时可用信息 |
| T13 | 关键行情或来源不可访问 | 显示延迟和缺口，不伪造实时价格、全文或预测 |
| T14 | 用户在公司或关系上提问 | 实际产生研究任务、来源回答和可追溯回写；失败状态可见 |

这些测试验证规则和流程正确，不承诺短期收益。尤其不能把“生成了日报”“页面能打开”或“问答听起来合理”作为研究完成的充分条件。

### 三层复盘

研究质量检查事实抽取、证据支持、原文追溯、去重、反证与关系传导。预测质量检查事前保存的经营指标、区间、期限和兑现条件。投资结果检查同一区间内的绝对收益与相对基准收益，并保留全部成功、失败和待判断记录。

建议同时保留原期限的预测评估和后续买卖变化记录。原建议被修订或卖出后仍可看到当时预测；新建议采用新的起点，不回填旧预测。信号生效价、交易成本与税前口径需要预先定义，避免将不可获得的收盘价当作可执行成交价。

历史回放用于检查流程、数据时点和更新逻辑。模型可能已知历史事件的后续结果，因此不能仅凭回放收益认定投资能力；需要持续保存真实时间下的前向建议，并在约定季度至一年窗口复盘。

发现错误要定位到来源、业务机制、关系传导、财务预测、价格预期、基准预测或时点判断。修改模型与规则需保留原因和版本，不能为了让过去成绩更好而事后换基准或删除失败建议。
