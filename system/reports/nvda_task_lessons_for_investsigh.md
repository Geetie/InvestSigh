## §1 那份任务实际长什么样（供对照，非本文件重点）

- **方法**：老板四条方法论（先建全景再谈标的 / 三级信息分层 / 叙事→期望→内在价值 / **共识及其变化是一等公民**）

  （"生意质量顶级 ROIC 81.66%，但十年 IRR 乐观 +11.88% / 中性 +6.65% / 悲观 −0.92% —— **好公司，价格已付掉了它的好**"）。

## §2 ★ 对本项目最有价值的 6 条（按价值排序）

### 2.1 ★★★ 它用**真实跑**验证能力，并**实测出"共识层零覆盖"** —— 而本项目恰有这块设计

它判定三个包第四条（共识）**完全缺失**，且这是"老板最看重、明说是一等公民"的一条。
逐包核查（它自己列的）：`thesis-drift` 检的是**自己的论点**漂移、`thesis-tracker` 是自己的假设清单、
`news-pulse` 抓的是**个人意见**、`investment-team` 是**内部多视角** —— **全都不等于"市场共识分布"**。
**三包加起来提供的支持是零**。因此 Phase 4 的共识数据**全靠包外取**（`stockanalysis/forecast`、
`westock-mcp`、WebSearch）。

**★ 对本项目的双向价值**：

**(a) 它给出了"共识层"的具体口径与框架 —— 这正是本项目 `Ch5` 缺的方法论。**
本项目有 `Ch5 价格与市场预期研究` + `facts/expectations.jsonl` + `ExpectationSample` 模型，
**有"预期"的表，但没有"共识"的方法**。它自建的框架可以直接作为 `Ch5` 拆解的输入：

| 它的自建件 | 内容（逐字要点） | 可落到本项目 |
|---|---|---|
| **共识饱和度三层次** | ① **共识是否在变**：看评级分布时间序列；连续 3–6 个月不动 = "共识冻结" = 已知信息已被定价、坏消息无缓冲<br>② **价格是否还对利好反应**：找一次"规格极高"的利好，算净涨幅与回吐；净涨幅 <5% 且回吐 >4% = 价格钝化<br>③ **叙事主题是否在替换**：看"公司被问的问题"变没变；看质疑方层级（民间媒体 → IMF/BIS → 国会/监管 = 升级信号） | `Ch5` 的"市场预期"研究骨架 |
| **一句最有说服力的结论** | **把共识的 FY+2 增速与自己的"乐观情景"对照；若二者接近，说明"你的乐观情景就是共识"** | 这是一个**可判定的判据**，可进 `Ch5` |
| **共识取数入口** | 分析师数量/共识评级/目标价均值·中位数·高低、**评级分布时间序列**、FY+1·FY+2 一致预期、价格历史（判断利好是否已被定价） | 可直接补进 `rules/data-sources.allowlist.yaml` 的"取数入口"层（见 2.2） |

**(b) 反过来，本项目应当把"共识层"当作自身能力清单里的一项明确交付**，而不是只留一张 `expectations` 表。
**否则本项目会重演它的判定："四条方法论少一条，而少的那条是一等公民"。**

**建议**：登记为本项目 `Ch5` 的**方法补强项**（`S-1`），由需求方裁定是否纳入 `01_`~`11_` 拆解。

### 2.2 ★★★ "没有产出模板 → 每次从零手搓 → **跨报告不可比**"（它自评产出物标准化仅 45/100）

它自评的四样**全部自建**：分层地图 · 共识快照 · 排序框架 · 论点健康度评分。

### 2.3 ★★★ 它的工具层暴露了 3 个"**不鲁棒判据**"缺陷，其中一个**把正确的数据判成错的**

| # | 缺陷 | 现象（逐字） | 它给的修法 |
|---|---|---|---|
| 1 | `cross-validate` 用**中位数**作基准 | BVPS 四源 `9.48 / 9.50 / 8.20 / 4.11` → 中位数被 4.11 拉到 8.84 → **正确的 9.48 也被判 ❌（偏差 7.24%）** | 改用 **IQR / MAD** 离群点检测；样本 ≥4 时先剔除最大离群值再定基准 |
| 2 | `report_audit extract` **正则从散文误抓数字** | 从 `"FY2026"` 抓出 `2026.00`、从 `"10-K"` 抓出 `10.00` → **18 项抽检里 2 项是噪声（11% 抽样预算）** | 加标签白名单，过滤明显非数据点的行 |
| 3 | `audit --discrete-risks` **格式脆弱** | 分隔符必须是 ASCII 逗号；写成 `→` 或 `;` 一律报错（**踩坑 2 次**） | help 给可复制示例 |

**★ 为什么这条对本项目价值最高**：这正是本项目 `CONVENTIONS.md::R-06` 的核心关切，
而且它给了一个**具体的负面样本**与**正面修法**：

- **[缺陷 1] 是"基准值本身不鲁棒"** —— 判据没错（双源比对），但**基准取法错了**，
  后果是**误报**（把对的判成错的）。本项目 `R-06` 已写"宁可漏报不可吵"，
  这条是"**误报的具体来源**"的教科书案例。
  → **可直接借用为一条自检**：**任何"基准/参考值"型判据，必须追问"这个基准会不会被离群值带偏"。**
  本项目的 `scripts/benchmark/return_guard.py`（基准收益口径唯一真源）与
  `conflict_scan`（P-03/P-05/P-07 schema）都值得照此自检。
- **[缺陷 2] 是"抽样预算被噪声吃掉"** —— 本项目 `report` 类抽取（如 `trace/traceback.py`）同理。
- **它还有一条通用铁律**：**"报告表格一格一指标。不要把两个数字塞进同一格——机器会误读，人也会。"**
  这正是本项目 `NumericClaim`（9 字段）与 `DerivedValue{formula, operands, method_version}` 的设计取向的**外部佐证**。

### 2.6 ★★ 它的**环境踩坑**与本项目**惊人同源** —— "工具链自身会静默毁掉验证"

## §4 我**不建议**照搬的（避免技术债）

1. ★ **不照搬它的 5 维加权排序与 8 维健康度评分**。
   它用"需求可见度 25% / 瓶颈硬度 25% / 预期空间 15% / 估值安全边际 20% / 风险可测性 15%"加权，
   以及满分 100 的 8 维论点健康度。
   **本项目明令禁止这类形态**：`P-09` + 施工图 `§8 纪律 1` —— 决策作用域内**参数不得内置阈值**、
   代码**不得**出现 `weight` / `score` 等命中词；`R-06` 也要求判据"**可判定 + 穷尽**"，
   而加权分数是**不可判定的合成量**。
   → **这不是本项目错了**，而是一个**真实的设计取向差异**，代价与好处都明确：
   - 好处：判据可判定、可复用、可审计（`DerivedValue` 可追到 operand）；
   - 代价：**缺一个"多因素综合比较"的机制** —— 它靠加权分数把 6 个候选排成一列，本项目目前**没有等价物**。
   → **应登记为张力**（`T-09`）：需求方若也要"排序表"，须裁定用何种**非加权**的可判定机制
     （例如分层偏序、逐维度支配关系、或把权重外置到 `rules/` 由需求方冻结）。
2. **不照搬**三个 skill 包的组织形态（22 子 skill / `tools/` 脚本集）—— 本项目用**章节拆解 + 门禁**，
   更适配"可验收"；引入外部包会让"设计权威"分裂成两处（`§2.2 第 1 条` 的初衷）。
3. **不照搬**它的目录约定（`reports\英伟达\`、`ai-berkshire/reports/`）—— 本项目有
   "18 JSONL 唯一真源 + `views/` + `snapshots/`"的既有契约，**不要混入第二套**。
4. **不照搬** `Serenity` 的 `serenity_scorecard.py` —— 与第 1 条同理（第二套裁决口径，违反 `G-06`）。
5. **不照搬**它"用 `WebSearch` 取 IMF/BIS/国会表态作为共识证据"的做法（那是**它的**三/二级来源）；
   本项目有 `SourceTier` 与 `locator_check`，**要求落回一级**。

## §6 一句话结论

那份任务最值得吸收的**不是**它的工具链，而是**它自己实测出来的三件事**：

1. **「共识层」是这套方法论的空白**，而它恰好是需求方最看重的一条 —— **本项目有 `expectations` 表但缺方法**，必须补（`S-1`）；
2. **"产出物标准化"是它自评最低的一项（45/100）**，因为"换个 Agent 重跑会长成完全不同的样子，跨报告不可比"
   ——**这恰是本项目存在的理由**（18 JSONL + schema + 门禁），且本项目还缺"传导矩阵的强度/时滞"（`S-2`）；
3. **"不鲁棒判据"会**误报**（把对的判成错的）** —— 它实测的 `cross-validate` 中位数被离群值拉偏，
   与本项目 `R-06` **同源**，且提供了一个具体自检动作（`S-4`）。

**并且发现一处真正的设计冲突**：它用**加权打分**做排序，本项目**明令禁止**（`P-09` / `纪律 1` / `R-06`）。
两边都不是错的，但**本项目因此缺一个"多因素综合比较"机制** —— 建议登记为张力 `T-09` 由需求方裁定（`S-3`）。
