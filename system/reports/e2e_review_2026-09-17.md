## 3. 三条系统级缺陷：核验

### 3.1 `stage_gate` 假红 —— **根因判断成立，位置表述需修订**（+ 我补出触发链）

**报告表述**：「首日豁免谓词（`stage_gate` 用）| `scripts/delivery/stage_gate.py:640` 起 | `holds_valid_result()`」

**核验**：`holds_valid_result()` 定义在 **`scripts/daily/degrade.py:152`**，
而 `stage_gate.py:630` 是 **`from scripts.daily.degrade import holds_valid_result`**（**import，不是另写一套**）。
`stage_gate.py:622-624` 的注释逐字记载"`G-45` 收口……本模块**不再自持一套**"。
⇒ **"两个谓词打架"这个说法容易读成"两处实现"**，应订正为「**同一模块内两个分工不同的谓词，被一条判据交叉使用而打架**」。

**但根因完全成立**，我做了决定性实证：

| 谓词 | 认什么 | 对今天这批行 |
|---|---|---|
| `is_valid_run_record()`（`degrade.py:129`） | 带 `check_record` 且 `status≠failed` 且 `degraded=False` | **4 条运行记录全 failed + degraded=True ⇒ 全 False** |
| `holds_valid_result()`（`degrade.py:152`） | **并集**：① `last_valid_result_ref` ② `is_valid_run_record` ③ `status=="done"` 且 `output_refs` 非空 | 3 条 review 行走**载体③** ⇒ **True** |

实测两个读数：

```
last_valid_result_ref(root) = None          ← 写路径只能给 None
holds_valid_result(task_review::*::*) = True ← 判据认为"存在可保留结果"
```

⇒ 判据说"前序有行持有有效结果 ⇒ 失败行**必须**有引用"，写路径却**只能给 `None`**
⇒ **要求引用一个写路径产不出的东西** ⇒ 结构性不可能 ⇒ **假红** ✓ 报告判断正确。

**★ 报告没指出的触发链**（我补出）：这条假红的**触发器正是 `record_eval` 写的 3 条 review 行** ——
它们 `status=done` + `output_refs` 非空、**但不带 `check_record`**。追加序实测：

```
idx 2  task_check_2026-09-16_full        failed   check_id=check_2026-09-16_full
idx 3  task_check_2026-09-16_full_r1     failed   check_id=check_2026-09-16_full_r1
idx 4-6  task_review::* (无 output_refs)  done
idx 7-9  task_review::* (有 output_refs)  done     ← ★ 载体③ 从这里开始成立
idx 10 task_check_2026-09-17_full        failed   ← 前面已有载体③ ⇒ 不再豁免 ⇒ 判红
idx 11 task_degrade::2026-09-17::full    failed
idx 24 task_check_2026-09-17_full_r1     failed   ← 同样判红
```

⇒ 09-16 的失败运行排在 review 行**之前**（首日豁免），09-17 的排在**之后**（第一次不豁免）。
**与报告"第二次日更必然红"的推断一致，且给出了精确的机制边界。**

### 3.2 `no_signal_day` 判红 —— **门禁正确**；我怀疑过的"自相矛盾"是**假象**

我一开始看到输出里**同一条文案既 `HISTORICAL` 又 `FATAL`**，怀疑门禁自相矛盾。**核验后推翻**：

```
no_signal_day.py:165  effective, superseded = _latest_per_run_date(check_records)
no_signal_day.py:170  report.violations += check_signal_change_ratio(recs, effective)      ← FATAL
no_signal_day.py:177  for viol in check_signal_change_ratio(recs, superseded):             ← 只 note
no_signal_day.py:179      report.notes.append("HISTORICAL(superseded revision, not a violation): ...")
```

⇒ **`effective` 判 FATAL、`superseded` 只打 note**，两条**是不同记录**
（`check_2026-09-17_full_r1` vs `check_2026-09-17_full`），只因两者 `changed` 都是 `False` 而**文案相同**。
⇒ 报告"门禁是对的"**核实成立**；且 `_r1` 修订**并没有真的修掉问题**，只是把违规从"历史"挪到"当前"。

**★ 但这暴露一处两个判据的口径不一致**（报告未指出）：

| 判据 | 对"同日重跑"的处理 | 后果 |
|---|---|---|
| `no_signal_day` | 按 `run_date` **去重**，只看最新（旧修订具名 note） | 一天最多 1 条 |
| `stage_gate::degrade_keeps_last_valid` | **不去重** | ★ **每多跑一次就多一条假红**（实测 2 → 3 条） |

⇒ 建议：`stage_gate` 采用同族的"每个 `run_date` 只看最新"口径，旧修订仍以 note **具名可见**
—— 这是**降噪不放松**（与 `no_signal_day` 的依据 `G-RC-04` 同源）。
