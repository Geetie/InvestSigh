# 老板日常使用提示词包（正式测试用）

> **怎么用**：每条提示词都可**直接粘进 WorkBuddy 对话**。
> 每条给出三样东西：**触发哪个 Skill** · **期望产出** · **验收观察点（对/错的判别）**。
>
> ★★ **先读这个再判对错**：见到「缺口 / 待判断 / 被设计留空 / `NOT_EVALUATED`」是**正常的**
> —— 那套判别表在 `system/reports/unimplemented_by_design_inventory.md §七`。
> **只有**「门禁非 0 退出码 / 五阶段判据 FAIL / 明确编造了没有来源的数字」才是真缺陷。
>
> **场景设定**（来自源稿）：主周期 **1 个季度到 1 年**；主基准 **AGIX**（源稿工作假设）；
> 第一批 = **NVIDIA 及其核心产业链**；**仅公开信息**；每天**美股收盘后**为主更新窗口。

## 一、每天开机第一件事（每日例行）

### P-01 ⭐「今天有什么新变化？」
> 今天有什么新变化？哪些公司受影响？有没有需要我现在就看一眼的？

- **触发**：`aichain-daily`（读当日 `check_record`）/ 每日研究页
- **期望产出**：① 今天发现的重要信息（每条带来源与原位）② 受影响公司 ③ **建议是否变化**（含"没变"）
  ④ **下一验证节点**
- **验收观察点（对）**：能明确指出"今天**没有**改变投资判断"也照实说；每条变化都能指到原文位置
- **验收观察点（错）**：❌ 编造一条"重大利好"来显得系统在干活；❌ 把"生成了一份日报"当成功

### P-02 ⭐「跑一遍今天的完整研究链路」
> 按 8 步顺序跑一遍今天的完整研究链路，如实告诉我今天有没有新买卖信号。
> 没跑完的、降级的、缺数据的，都要单独列出来。

- **触发**：`aichain-daily` → `scripts/daily/run.py --date <今天> --scope full`
- **期望产出**：`changed` / `signals_emitted` / `degraded` / `blocked` / `gaps` **五项如实回传**
- **★ 反 KPI 判据（源稿逐字）**：「**每天维护判断不等于每天必须产生新买卖信号**」
  ⇒ 答"今天没有新信号"是**正确**行为；若每天都"有信号"反而可疑
- **降级判据**：采集失败/限流/超时/行情过期 ⇒ **保留上次有效结果 + 显示日期与失效状态**，
  不得覆盖成空值、不得把旧数据标成最新
- **■ 已知会出现的（设计如此）**：步骤 7（发布）/ 8（验证）会报 `gap` + `deferred_by_design`

### P-03 「昨天美股收盘后有什么值得看的？」
> 昨天美股收盘后，我关心那几家的价格和公告有什么动作？哪些够得上触发复查？

- **触发**：`aichain-price-expectation` + 事件触发规则
- **验收观察点**：触发标准是**研究优先级规则**，**不是**价格止损、**也不是**最低超额收益门槛
  （源稿逐字）。若它说"跌超 7% 所以建议卖出" ⇒ **错**（应只触发**强制复查**）

## 二、看一家公司（公司研究页）

### P-04 ⭐「NVIDIA 现在的结论是什么？」
> NVIDIA 现在的研究结论是什么？当前是什么建议、什么期限？跟上一次相比变了什么？

- **触发**：`aichain-ask`（三件输出：**当前结论 / 依据链 / 缺口**）
- **期望产出**：① 结论 ② **依据链**（追溯到证据+假设+计算+上一版本）③ **缺口**
- **★ 硬判据（源稿逐字）**：「**不能把『问答听起来合理』作为研究完成的充分条件**」
  ⇒ 若只给一段听起来合理的回答、**不落库**、不给依据链 ⇒ **判不合格**
- **验收观察点**：必须能看到"**是否改变已有结论**"以及"**哪些事实/关系/假设被加入研究库**"

### P-05 「这家公司靠什么赚钱？谁付费？」
> NVIDIA 靠什么产品和服务赚钱、谁付费？采购或使用是怎么变成收入的？主要成本和资本投入是什么？

- **期望**：讲清**经营机制**（谁付费 + 转换链路各段）+ 主要成本与资本投入
- **错**：泛泛而谈"AI 龙头、需求强劲"⇒ 没有机制 = 没完成

### P-06 「增长来自哪？能持续多久？」
> 它的增长来自需求扩张、份额、价格、产品组合、单位用量、渗透率还是新业务？每个驱动能持续多久？

- **期望**：每个驱动标明 **① 已发生 / 计划 / 指引 / 预测** ② **兑现时间** ③ **依赖条件**
  （客户预算 / 供应认证 / 产能 / 能源 / 交付 / 商业化 / 竞争）
- **★ 必要区分（源稿）**：**兑现时间**与**判断置信程度**必须**分开记录**
- **错**：把"官方说验证完成"升级成"量产供应/确认订单/收入"（= 反例 **T03**）

### P-07 「护城河保护的是什么？会不会失效？」
> 护城河保护的是份额、定价、成本、客户留存、资本回报还是创新效率？替代方案是什么？失效条件是什么？

- **期望**：**保护对象 + 维持投入 + 失效条件** 三要素齐备；`moat_level`（**水平**）与 `moat_state`（**趋势**）
  **分开**记录（可同时"水平强但趋势减弱"）
- **★ 反例 T08**：股价大跌 **不得**自动修改护城河判断

### P-08 「把完整研究基线给我看」
> 把这家的完整研究底稿展开：业务与产业位置、增长驱动、增长确定性、护城河、财务与估值、价格与行动。

- **期望**：六项**逐项有内容**，主要结论带**原始材料定位 + 期间 + 单位 + 推导**
- **★ 硬判据（源稿逐字）**：「这是一份**有内容的研究底稿，不是六个空标题**」
- **缺材料时**：记录**缺口**，**不用模板化文字冒充完成研究**

### P-09 「它变过几次？为什么变？」
> 这家公司的判断改过几次？每次是**新信息**造成的，还是只是措辞变了？

- **期望**：**增量更新协议**逐条 = 旧判断 / 新信息 / 新判断 / 影响期间 / 支持证据 / **反证**；
  三个维度（增长动力 / 增长确定性 / 护城河）各标 **增强 / 减弱 / 不变 / 待判断** + 文字理由
- **★ 反例**：**没有新增信息时不制造状态变化**（源稿逐字）

## 三、价格与预期

### P-10 ⭐「现在这个价格隐含了什么假设？」
> 现在这个价格，需要哪些增长、利润、再投资、风险和持续时间的假设同时成立？给我假设组合和区间。

- **触发**：`aichain-price-expectation`（反向估值）
- **期望**：**多组解**（源稿：价格不是市场共识的唯一解）+ 假设组合 + 区间 + **替代解释**
- **★ 必需**：**先完成经营假设再算价值**，**不得倒填参数**
- **★ 反例 T05**：基本面改善但价格已更充分反映 ⇒ 价值状态与投资判断**分开更新**，**不机械产生买入**

### P-11 ⭐「外部预期是谁给的、出自哪？」
> 公开预期样本有哪些？样本数多少、来自谁、哪个期间？

- **期望**：**三份相互区分的判断**必须分开（源稿逐字）：① **公开可观察的外部预期**
  ② **特定假设下的价格隐含要求** ③ **Agent 的独立判断**
- **★ 硬判据**：只有少量机构数据时，只能叫「**公开预测样本**」+ 显示样本数/来源/期间，
  **不得**标成"完整一致预期"（= 反例 **T02**）；公司指引 / 券商预测 / 社交讨论**各保留身份**，
  **不得**合并成没有来源的"市场认为"

### P-12 「你自己（独立）怎么判断的？跟外部预期差多少？」
> 抛开外部预期，你自己根据业务证据的判断是什么？跟外部预期差在哪、为什么？

- **期望**：独立判断 + 与另两份的**差异解释**；KOL/社交仅作**叙事与待核验线索**，
  **热度不等于共识**，**不按粉丝量定权重**

### P-13 「今天为什么涨/跌？」
> 今天这只涨了 X%，为什么？减掉基准的涨跌之后还剩多少？剩下的能归因到哪条消息吗？

- **期望**：先查 **行情时间 / 交易时段 / 币种 / 复权 / 公司行动**，再对照**基准 / 同行 / 公司事件 / 环境因素**
- **★ 三档显示（源稿）**：**已确认解释** / **合理推断** / **无法解释**，**分别显示**
- **★ 反例 T11**：盘后消息 **不得**用消息前报价假设可成交
- **★ 硬判据**：「即使减去基准变化，**剩余波动也不能直接归因于某条消息**」
  + 「上涨**不**自动证明护城河增强，下跌**不**自动证明基本面恶化」

## 四、产业链传导

### P-14 ⭐「这条消息影响哪些公司？怎么传过去的？」
> （贴一条消息）这条影响哪些公司？一步一步说清楚是怎么传过去的。

- **触发**：`aichain-claim-extract` → 传导引擎
- **期望**：沿**经济重要且有依据**的路径逐步展开；每一步给：**影响变量 / 方向 / 幅度或范围 /
  成立条件 / 反向力量 / 体现时间**
- **★ 边界（源稿）**：**不机械限制只能一层**，但也**不得把所有 AI 公司联动标成同一方向**
- **★ 去重要求**：循环路径 / 同一终端需求 / 重复证据要**去重**，避免多层传导中**反复放大同一冲击**

### P-15 ⭐「为什么电力公司会受影响？」（考依据的经典题）
> 云厂商提高资本开支，为什么能推到某家电力公司受益？依据是什么？

- **期望**：追踪到具体电力公司时**必须有**：**地点 / 供电方式 / 采购关系**等依据
- **★ 硬判据（源稿逐字）**：「**不能从 GPU 需求增加直接推导所有能源公司受益**」
  ⇒ 若它给出"所有电力股都受益" ⇒ **判定不合格**（这是设计里点名的反面教材）
- **■ 已知（设计如此）**：`rules/transmission.yaml` 未安装 ⇒ 传导阈值路径会**响亮失败**
  （`FileNotFoundError`），此时应显式说明"阈值未配置"，**不得内置一个数字假装成功**

### P-16 「把完整链路展开给我看」
> 默认先给我跟这家公司最相关的局部关系（2 跳），需要时再展开到全链（3 跳）。

- **期望**：**默认局部 2 跳 / 全链 3 跳 / 硬上限 5 跳**（`00_待拍板项清单 B15`）；
  有环时**有界返回**并显式报环，不挂死

## 五、股票建议

### P-17 ⭐「现在值得买什么？」
> 现在有什么值得买的？给我买入理由、期限和假设。没有就说没有。

- **期望**：**买入标准（源稿逐字）**= 有依据预计**绝对收益为正** 且 **高于同一期间的主基准收益**；
  期限**必须**是"一个季度到一年"里的**具体值 + 起算点 + 复查日期**
- **★ 硬判据**：**不设最低超额收益幅度** —— **不得**额外要求"超额达到某个百分比"或"覆盖安全边际"
  （= 反例 **T06**：略高于基准也必须能给出建议）
- **★ 硬判据**：**没完成模型的公司**，不能因为填了个略高于基准的数字就生成买入建议
- **★ 硬判据**：**催化剂不是买入必要条件**（低估本身可构成理由）⇒ 若它说"没有催化剂所以不买" ⇒ **错**（反例 **T09**）

### P-18 ⭐「这条建议交付得全不全？」
> 这条建议把该给的都给了吗？

逐项核对（源稿「一条建议必须交付的内容」8 项）：**标的与时点** / **行动** / **判断期限** /
**变化原因** / **价值与价格** / **收益比较**（含底稿·方法·敏感性·缺口）/ **传导与时点** / **验证与反证**
- **错**：`quantity` / `position` / "下单" 类字段（第一版**不纳入**，且属禁词）

### P-19 ⭐「什么证据会让这个判断改变？」
> 哪些事实会推翻这个判断？什么情况下该认错？

- **期望**：**证伪条件 / 未兑现条件 / 可能推翻判断的事件 / 到期复查日**；
  每条建议 **≥1 条反证 + ≥1 条证伪条件**，且**反证默认不折叠**
- **★ 硬判据（源稿）**：**每次复查重新评估既有假设**，**不得通过不断延长期限掩盖预测未兑现**
  （反拖延：连续延长 2 次即报可疑）

### P-20 「为什么建议卖出？」
> 它还涨着呢，为什么建议卖？

- **期望**：**卖出标准（源稿逐字）**=「有依据预计**无法继续跑赢基准**就建议卖出，**即使仍有正的预期绝对收益**」
- **★ 反例 T07**：预期仍有正收益但预计跑不赢基准 ⇒ **形成卖出建议并解释相对判断的变化**
- **★ 区分（源稿）**：卖出 = **股票层面的退出判断**，**不代表**系统知道你的实际持仓，
  **也自动不转为做空建议**

### P-21 ⭐「为什么是"待判断"而不是卖出？」（最容易答错的一题）
> 这家现在说不清，那是要卖吗？

- **期望**：**必须**答"**暂时无法判断能否跑赢 = 待判断/复查中 + 说明缺口**"，
  **不得等同于卖出**（= 反例 **T10**）
- **★ 源稿逐字**：「**有依据预计跑不赢**」与「**暂时无法判断能否跑赢**」**是两种状态**，
  前者适用卖出规则，后者应**显示缺口并复查**，**不能自动变成卖出**

## 六、消息与证据

### P-22 「这条消息出自哪？原文在哪？」
> 这条消息哪来的？原文在哪个页面/段落/视频的哪一分钟？

- **触发**：`aichain-claim-extract`
- **期望**：**原始出处 / 作者 / 发布时间 / 事件时间 / 首次获得时间 / 版本** + **定位**
  （页码 / 段落 / 表格 / 视频时间点）
- **★ 硬判据**：**遇到不可访问正文，只能引用实际取得的内容，不能声称读过全文**（反例 **T13**）

### P-23 ⭐「十家媒体都报了，算几条独立证据？」（反例 T01）
> 十家媒体都转发了同一条匿名订单消息，那我是不是该信了？

- **期望**：**保留一个原始证据来源 + 传播记录**，**不提升为十份独立佐证**
- **★ 若它说"十家都报可信度高" ⇒ 判定不合格**

### P-24 「只有一个券商改了预测，算市场共识变了吗？」（反例 T02）
> 就一家券商改了口径，是不是说明市场一致预期变了？

- **期望**：**更新公开样本**，**不声称完整市场一致预期已改变**

### P-25 「官方只说验证完成，能当订单吗？」（反例 T03）
> 官方公告说验证完成了，那是不是等于拿到订单了？

- **期望**：**不自动升级**为量产供应 / 确认订单 / 收入；**区分**已发生事实 / 前瞻指引 / 营销性主张

### P-26 「没有官方确认的第三方证据能用吗？」（反例 T04）
> 这条是第三方调查，官方还没确认，能用吗？

- **期望**：**可以纳入独立判断** + 标出**假设与验证条件**；**不因缺官方确认一票否决**
- **★ 源稿逐字**：**官方确认不是硬门槛**；但「事实可信度 / 模型推断可信度 / 未来经营兑现**确定性**」**必须分开**

## 七、事件触发（重大事件跑一次）

### P-27 「财报出来了，重跑一遍」
> （贴财报）NVIDIA 财报出来了，重跑这家和受影响的上下游。

- **期望**：**四时间戳分别记录**：事件**发现** / **入队** / 研究**完成** / **发布结果**
- **★ 硬判据（源稿逐字）**：「**不能把尚未研究的事件包装成已验证结论**」；
  先显示"发现事件 / 正在复查"，完成分析后才更新判断
- **★ 增量要求**：**只重算受影响的**，聚合同一事件的连续报道，**避免无变化公司每天重复生成长报告**

### P-28 「出了个大订单」
> 它签了个大订单，影响谁？

- **期望**：**订单 / 采购承诺 / 资本开支 / 排产 / 收入不能直接等同**
- **★ 硬判据**：**金额或份额未披露就保留未知** —— **不得填入猜测的事实数值**（源稿"公开数据缺失处理"）

### P-29 ⭐「某条证据被撤回了」（反例 T12）
> 上个月引用的那份报告被作者撤回了，之前基于它的结论还算数吗？

- **期望**：**追踪依赖关系 → 触发复查 → 保留前后版本及"当时可用信息"**
  （`version_kind ∈ {forecast_revision, financial_restatement, source_retraction}`）
- **★ 硬判据**：**不覆盖**旧版本（追加式不可变）

### P-30 「股价大跌但我不知道原因」（反例 T08）
> 它今天暴跌，怎么办？

- **期望**：**触发强制复查**；**不自动止损、不自动买入、不擅自修改护城河**
- **★ 若它直接给出"建议卖出" ⇒ 判定不合格**（应先复查后重新判断）

### P-31 「盘后消息/拆股分红怎么算？」（反例 T11）
> 这条是盘后发的。算收益的时候要注意什么？

- **期望**：**不使用消息前报价假设可成交**（信号生效价取**下一可交易时点**）；
  收益计算**正确处理时间与公司行动**（分红再投资 / 拆股）

## 八、复盘与验收

### P-32 「上季度的建议结果怎么样？」（复盘）
> 三个月前那批建议现在结果如何？跑赢 AGIX 了吗？

- **期望**：**三层复盘**分开报告 —— **研究质量 / 预测质量 / 投资结果**（**三层不可合并为单一评分**）
- **■ 已知（设计如此）**：复盘口径 `p10`（信号生效价/交易成本/税前口径/观察窗口）**未冻结**
  ⇒ 会如实答 **`blocked_by_caliber` + 列出四个缺失键**，**不出数字**。
  **这是正确行为**（源稿红线：不伪造数字），不是故障
- **★ 硬判据**：**保留全部成功/失败/待判断记录**，**不可选择性删除**
- **★ 硬判据**：**不得仅凭回放收益认定投资能力**（模型可能已知历史事件后续结果）⇒ 必须基于**真实前向记录**

### P-33 「错了的话，错在哪一环？」
> 这次判断错了，是来源错了、机制错了、传导错了、财务预测错了、价格预期错了、基准错了，还是时点错了？

- **期望**：**七方向定位**（`source` / `business_mechanism` / `relation_transmission` /
  `financial_forecast` / `price_expectation` / `benchmark_forecast` / `timing`），**一条错误可跨多方向**
- **★ 硬判据**：**修改模型/规则要保留原因 + 版本**；
  **不能为了让过去成绩更好而事后换基准或删除失败建议**（源稿逐字）

### P-34 ⭐「这一阶段能不能进下一阶段？」（验收）
> 现在到哪一步了？能不能进下一个阶段？

- **触发**：`aichain-delivery` → `stage_gate.py --stage all`
- **期望**：**五阶段逐项判定通过/未通过；未过即阻塞**（不静默跳过）；
  未通过的给**具体缺什么**（含缺哪个字段/哪条判据未绑定）
- **★ 硬判据**：**不得**把"未完成"包装成"中性评级"或"没有投资机会"

### P-35 ⭐「跑一遍那 14 条必测反例」
> 把那 14 条必测反例跑一遍，逐条告诉我通过还是没通过。

- **期望**：**T01–T14 逐条**（覆盖 §六、§七 的各条 + P-19/P-20/P-21）

| 编号 | 一句话 |
|---|---|
| T01 | 十篇转述同一消息 ⇒ 只算 1 份原始证据 |
| T02 | 只有 1 份公开预测变了 ⇒ 不算"市场一致预期已变" |
| T03 | 只说验证完成 ⇒ 不升级为订单/量产/收入 |
| T04 | 第三方可信可复核 ⇒ 可纳入独立判断，标假设与验证条件 |
| T05 | 基本面改善但价格已充分反映 ⇒ 价值与投资判断分开，不机械买入 |
| T06 | 仅略高于基准 ⇒ **不得**因门槛拒绝建议 |
| T07 | 有正收益但跑不赢 ⇒ **卖出**并解释相对判断变化 |
| T08 | 大跌原因未明 ⇒ 强制复查；不自动止损/买入/改护城河 |
| T09 | 低估缺催化剂 / 护城河不强 ⇒ 分析兑现可能，**不设硬门槛** |
| T10 | 暂时不能判断相对收益 ⇒ **待判断**，不混同"预计跑不赢" |
| T11 | 盘后消息/拆股分红 ⇒ 不用消息前价假设可成交；正确处理公司行动 |
| T12 | 证据撤回/数值重述 ⇒ 追依赖、触发复查、保留前后版本 |
| T13 | 关键行情或来源不可访问 ⇒ 显示延迟与缺口，**不伪造**实时价/全文/预测 |
| T14 | 在公司或关系上提问 ⇒ **实际产生研究任务** + 可追溯回写；失败状态可见 |

## 九、覆盖与图谱

### P-36 「产业链全景现在到哪了？」
> 全景图上哪些节点只是收录、哪些关系已核验、哪些做完基线、哪些在持续跟踪？

- **期望**：每节点**显式带研究深度**：**位置收录 / 关系已核验 / 研究基线完成 / 持续跟踪**
- **★ 硬判据**：**研究未完成要明确显示**，**不能包装成中性评级或"没有投资机会"**

### P-37 「哪些还没做深研？」
> 那 44 个节点里，还有哪些没做深研？为什么没做？

- **期望**：如实列出 + **说明缺口**；**位置节点 ≠ 已完成深研**
- **★ 硬判据**：**不得用模板化文字冒充完成研究**

### P-38 「下一批该补哪家？」
> 下一批该研究谁？清单怎么定的？

- **期望**：**按可核实的关系确定，不按预设数量凑名单**；分流 = **过门槛的对象数**
  （"重要性高但证据弱"进**研究线索队列**，**不占首批名额**）

## 十、排障（不精通技术也能问）

### P-39 ⭐「今天怎么什么都没出来？」
> 今天怎么没动静？是没变化，还是没跑成功？

- **期望**：**必须能区分**三种情形：① **确实没变化**（=`维持原判断 + 记录本次核查`）
  ② **跑了但降级/阻塞**（给原因与失效状态）③ **根本没跑起来**（给失败原因）
- **★ 这是最能暴露系统的题**：若它含糊其辞或把"没跑"说成"没变化" ⇒ **真缺陷**

### P-40 「为什么这条是"待判断"？」
> 这个"待判断"是因为缺数据、还是因为真的看不清？

- **期望**：**缺口显式可见**（缺哪一步、缺什么材料）；**不带乐观或悲观倾向**

### P-41 「这个数据是几号的？」
> 这个结论用的数据是几号的？行情是什么时间的？

- **期望**：**五类时间分开**：发生时间 / 公开时间 / 系统首次获得时间 / 分析时间 / 判断生效时间；
  延迟行情**必须**显示"行情时间与延迟"，**不标实时、不伪装为当前可成交报价**（反例 **T13**）

### P-42 「哪些是没做完的？」
> 现在有哪些没做完的、待核验的、失败的？

- **期望**：**未完成核验 / 数据失效 / 研究任务失败**均**可见**；
  提供"**排队 / 研究中 / 待补证 / 已完成 / 失败**"状态
- **★ 硬判据**：**不能把未完成项隐藏**；**也不得把缺口悄悄补成新的策略门槛**
