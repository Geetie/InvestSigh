## §2 两条流共同的硬约束（逐条）

- **W-1** 只在自己工作树（绝对路径）；**W-2** 绝不 `cd` 主仓库/他人工作树；**W-3** 绝不切分支。
- **G-2** 只白名单 `git add <文件>`；**G-3** 只在自己分支提交、**不做集成**；**G-4** 不写共享 git 状态；**G-7** 只回主理人。
- **V-01** 禁全量验证；**V-02** 每批独立超时；**V-03** 超时=不合格；**V-04** 沙箱外跑；**V-06** 新测试目录须报"需新增批次"。
- ★ **`V-08`（本批新增）**：宿主**每一轮有删除配额**（阈值 ~9999 项，`scope: "turn"`）。
  夹具"每用例复制 `system/` 用完即删"→ 一次全量 ≈ 3 万项删除 → **配额可能被耗尽**，
  此后连删单目录都被拒；**症状是"某批 1~40s 内提前红"，看起来完全像测试失败**。
  → **一轮内只跑一次全量；迭代用单批/单文件；反复迭代就新开一轮。**
- **R-06** 判据必须**可判定 + 穷尽**；禁关键词判据；允许清单优于禁止清单；优先运行时效果断言。
- **`rules/` 0444**：任何 `rules/**` 的新增/修改都**由主理人**按 `lock_rules.py` 流程执行；流内**只报告需求**。
- **`no_placeholder_guard`** 抹白注释与 docstring 但**保留字符串字面量** → 运行时文案避开其命中词
  （豁免清单 `system/config/placeholder_exemptions.yaml` 需**逐条登记**，默认无条目）。
