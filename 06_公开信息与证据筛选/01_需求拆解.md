# 第六章《公开信息与证据筛选》逐节需求拆解

> 分析对象：`02_可编辑源稿_v2.md` 第六章（第 165–207 行）。方法沿用第九章已验证范式：把浓缩句展开为可执行、可验收、可追溯的原子需求，每条判据结合第二/四/五/七/八/九/十/十一章语境裁定。
> 核心定位：**第六章是全系统的"信息入口闸门"**——它决定"什么信息能进来、进来后算多可信、能推动什么结论"。第九章（N9.1 来源与主张 / N9.3 来源登记）是它的存储底座；第十章 T01–T04、T13 是它的验收出口。
> 三条主轴（本章反复出现，务必对齐）：① **三维正交**——来源分级决定"先看什么"、证据质量决定"相信多少"、经济重要性决定"研究多深"；② **来源等级≠可信度**；③ **官方确认不是硬门槛**。
> **版本**：v1.1（2026-09-15 回改；**本文件回改明细见文末「附：回改记录」（唯一权威）**）

## 2. 深度挖掘专章

### 2.1 关于 6.2 分级（本章核心）

#### (a) 三维正交建模方案

| 维度 | 回答的问题 | 承载字段 | 取值/结构 | 判定主体 |
|---|---|---|---|---|
| **来源分级** | 先看什么（处理顺序） | `source.publisher_type`、`claim.tier`、`claim.origin_claim_id` | 一手/1.5手/二三手 + 判定依据 | 规则（主体类型 + 事实最初出处） |
| **证据质量** | 相信多少（可信度/权重） | `claim_quality.{direct_knowledge, method_reproducible, caliber_match, independent_corroboration, counter_evidence, interest_relationship}` | 六维各自结构化 | 混合（口径匹配/独立佐证=程序；知情/方法=模型+人工；利益关系=模型+人工） |
| **经济重要性** | 研究多深（投入上限） | `claim_impact.{affected_area, affected_node, magnitude, horizon}` | 改变驱动/兑现条件/护城河/价格预期 | 模型抽取 + 规则映射 |

**三轴如何组合决定"处理优先级"与"研究投入上限"**：

- **处理顺序优先级** = 主要受 `tier` 决定（一手先于 1.5 手先于二三手），再受重要性加权（高重要性的一手最先）。
- **研究投入上限** = 由 `经济重要性` 决定（cap）。低重要性主张即便是一手，也不做深度核验；高重要性主张无论来源等级都进入核验队列。
- **证据权重/置信** = 由 `证据质量` 决定，**只影响结论的置信与采纳，不影响处理顺序，也不能突破重要性设定的投入上限**。

**为什么不能压成一个分数**：
1. 三轴语义不同：序（order）、信（trust）、深（investment）。合并会丢失"高重要性但低可信"这一关键态——它需要的是"投入核验"而非"直接采纳"或"直接丢弃"。
2. 单一分数可被"刷量"操纵：高传播量/高热度来源会拉高总分，与 N6.3-14（禁止数量/情绪投票）直接冲突。
3. 单一分数会让"重要但不确定"被误当"低价值"而跳过核验，破坏第 6 步。
4. 原文明确禁止固定分数加权（N6.2/6.3），分数化即违规。

#### (b) 三个反例 → 可执行系统规则

| 原文反例 | 系统规则（可执行） | 承载字段 |
|---|---|---|
| 公司在社交平台发布的原始公告仍属公司来源 | 分级依据 `publisher_entity` 的主体类型，而非承载平台；当 `publisher_entity` 是公司官方账号时 `claim.tier=primary`，即使平台是 X | `publisher_entity`、`publisher_type=company_official` |
| KOL 引用财报时，相关事实回到原财报 | 引用型主张的**事实性内容**以"事实最初出处"定级：建立 `claim.origin_claim_id → 原始一手主张`，事实部分取源头 tier，转述者只记 `propagation`，不计独立证据 | `claim.origin_claim_id`、`claim.is_restatement` |
| 专业人士可复现实测也可能提供有价值的独立证据 | 分级（处理顺序）与质量（可信）解耦：`claim.tier` 仍按主体类型=非机构，但 `claim_quality.method_reproducible=true` 且可计入 `independent_corroboration`，从而进入独立证据 | `method_reproducible`、`independent_corroboration` |

#### (c) 1.5 手为什么单列

- **不对称性**：比一手多了"二次加工"（引用/估计/观点）；比二三手多了"专业方法与身份可核实"。并入一手会把券商的"估计/观点"污染为官方事实；并入二三手会丢掉"方法可复核 + 专业身份"的价值。
- **数据模型含义**：1.5 手材料必须**拆型存储**——一条 1.5 手报告 → N 条分型子主张：`original_investigation`（原始调查）/`citation`（引用，指向一手）/`estimate`（估计）/`opinion`（观点），各自带 own tier 与 quality。要求 `claim.claim_form` 细分 + `citation.origin_claim_id`。**这正是"分开提取"从文字变成 schema 的地方。**

#### (d) 不按粉丝量 → 替代机制

按以下顺序判定（权重由低到高，不合并为分数）：
1. **可复核的证据质量**（六维）——主要依据。
2. **独立佐证数量**（第 3 步的 `independent_evidence_count`）。
3. **与一手事实的一致性**（是否与官方披露冲突）。
4. **作者/来源的历史表现**，但**以人工核验样本为基准**（N9.3-09/11），且只用于**排序与提示**，不用于自动投票买卖。
> 必须禁止的做法：把粉丝量/点赞/播放量、文章数量、情绪强度写入任何决策函数（N6.2-07、N6.3-14）。

### 2.2 关于 6.1 信息边界

#### (a) "公开可阅读 ≠ 可稳定批量抓取" —— 三章之间的桥梁

| | 内容 |
|---|---|
| **第六章要什么** | 为每个来源定义"研究可行性契约"：访问方式、更新时间、可提取字段、采集限制、失败处理（N6.1-05~09） |
| **第九章给什么** | N9.3 来源登记（7 项）、N9.1-10（合法保留片段）、N9.1-28（失败原因）、N9.3-07（备选来源）、N9.2-06（服务端持久化） |
| **接口字段（建议 source_access 表）** | `{entry_url, obtainable_content_type, fetch_method, expected_latency, update_frequency, access_restriction, fallback_source, retention_scope}` |

**第六章 5 字段 ↔ 第九章 7 字段映射**（避免双份登记）：

| 第六章字段 | 第九章对应 | 需求ID |
|---|---|---|
| 访问方式 | 抓取方式 | N9.3-03 |
| 更新时间 | 更新频率 | N9.3-05 |

#### (b) 怎么"强制"不声称读过全文（而非靠自觉）

用**字段约束 + 程序校验**（N9.2-03 精神）：
1. `source.obtainable_content_type ∈ {full_text, summary, snippet, headline_only, no_transcript}`（**统一字段名**：包内不再用 `source.obtainable` 短名）。`no_transcript` = **有入口但无字幕/无正文**，与 `snippet`/`headline_only` 属同一"能拿到什么"维度、并列取值。
2. `claim.locator` 的类型受 `obtainable_content_type` 约束：`summary` 时 locator 只能是摘要行号，不得出现页码/段落。
3. `claim.full_text_read` 默认 false，仅当 `obtainable_content_type=full_text` 且 locator 合法时置 true。
4. **校验器**：任何 `full_text_read=true` 但来源非 full_text 的主张 → 校验失败、被拦截（程序判定，非模型）。
5. **展示层**：`full_text_read=false` 的主张自动标注"仅摘要/片段"。
> 与 N9.3-02 的关系：登记的可获得内容边界，决定该来源主张允许的 locator 上限——**来源登记是"闸门参数"，claim.locator 是"闸门输出"。**

#### (c) "公开数据 ≠ 零成本""未授权新增付费订阅"红线

- **红线**：首版不得以"引入新增付费数据订阅"来解决数据质量问题；任何付费数据接入须**单独提出并获授权**（N6.1-13）。公开来源的采集/模型调用/存储/部署成本是**允许且必须估算**的。
- **落在哪一章**：费用估算 → **第十一章**"公开数据与预算"参数；费用记录 → **第九章 N9.1-27（运行成本对象）+ N9.2-15（费用记录方案）**。

### 2.3 关于 6.3 七步主张化

#### (a) 步骤 → 输入对象 → 输出对象/字段 → 幂等键

| 步骤 | 输入对象 | 输出对象/字段 | 幂等键 |
|---|---|---|---|
| 1 保存出处 | 原始抓取物 | `Source`(+base locator) | `content_hash` / (`url`,`fetch_ts`) |
| 2 拆主张 | `Source` | `Claim`(主体/指标/期间/单位/`claim_nature`/`claim_form`/`official_claim_kind`) | (`source_id`,`locator`,`claim_form`) |
| 3 追踪去重 | `Claim` | `origin_claim_id`、`ClaimPropagation`、`dup_group_id` | (`claim_fingerprint`,`origin_claim_id`) |
| 4 质量判断 | `Claim` | `ClaimQuality`(六维) | (`claim_id`,`quality_version`) |
| 5 研究增量 | `Claim` + 研究基线 | `ClaimImpact`(驱动/条件/护城河/预期)、`archive_flag` | (`claim_id`,`baseline_id`) |
| 6 核验 | 重要且不确定的 `Claim` | `VerificationTask`、`alt_explanation`、`counter_evidence` | `task_idempotency_key` |
| 7 状态标注 | `Claim` | `ClaimStatus`(五态)、依赖结论更新 | (`claim_id`,`status_version`) |

#### (b) 第 3 步：独立 vs 转述

- **判定方法**：`claim_fingerprint = hash(主体, 指标, 期间, 单位, 数值/方向, origin_entity, time_bucket)`。
  - 若两条主张 fingerprint 相同**且** `origin_claim_id` 指向同一原始主张 → **转述**：只写 `ClaimPropagation`，`independent_evidence_count` 不增。
  - 若 fingerprint 相同**但**各自 `direct_knowledge=true` 且**无共同上游** → **独立佐证**：`independent_evidence_count` 递增。
- **设计**：`claim_propagation(propagated_from_claim_id, via_account, observed_at)`；`independent_evidence_count` 仅在 `is_independent=true` 时递增；`is_independent` 由"直接知情 + 无共同上游"两条规则判定（程序 + 人工兜底）。

#### (c) 第 4 步：六个质量维度的记录与判定主体

| 维度 | 记录方式 | 判定主体 |
|---|---|---|
| 是否直接知情 | `direct_knowledge ∈ {direct, indirect, unknown}` | 模型抽取 + 来源身份规则 |
| 方法可复核性 | `method_reproducible` + 方法段落定位 | 程序（是否含方法段）+ 人工抽样核验 |
| 口径匹配 | 期间/单位/币种/GAAP 对齐检查 | **程序**（N9.2-02/03） |
| 独立佐证 | `independent_corroboration[]` | **程序**（第 3 步计数） |
| 相反证据 | `counter_evidence[]` | 程序化检索 + 模型抽取 |
| 利益关系 | `interest_relationship` | 模型抽取 + 人工核验（关键主张） |

#### (d) 第 5 步："研究增量"是计算还是人工？"归档"的行为影响

- **半可计算**：`affected_area`（映射到驱动/兑现条件/护城河/价格预期节点）由模型抽取；`is_incremental` 由规则判定——**若主张未连接到任何基线节点，或与现有证据重复 → 无增量**。
- **归档 ≠ 删除**：归档主张不进入"待核验/驱动更新"队列、不触发基线更新、不参与建议证据集；但仍可被引用与回溯（满足第八章"保留可追溯历史"）。

#### (e) 第 6 步：预算闸门（可验收的行为定义）

- **谁设**：实现方配置（第十一章"检索/模型预算"待冻结）+ 研究优先级规则。
- **怎么算**：按任务类型设——时间预算（任务 deadline）/ 计算预算（模型调用数或 token 上限）。
- **到限时具体做什么**：停止深挖 → 将该主张标为 `pending_verification` → 生成**可重入的 `VerificationTask`**（含已得部分结论、替代解释线索、公开入口）→ 入队。
- **验收行为**：到限后任务状态=待核验且已入队、有日志、可重跑；**绝不静默丢弃、绝不把未完成结论标为已验证**。

#### (f) 第 7 步：五态状态机

**状态**：`有支持(supported)` / `有争议(disputed)` / `待核验(pending_verification)` / `被否定(refuted)` / `被新版本替代(superseded)`

| 转移 | 触发者 | 说明 |
|---|---|---|
| → pending_verification | 提取后初始态；或发现重要不确定 | 默认初始态 |
| pending → supported | 核验成功（程序 + 人工） | 独立佐证足且无强反证 |
| any → disputed | 发现相反证据 | 来源冲突 |
| any → refuted | 直接反证成立 | 可因反证被撤回而重开 |
| any → superseded | 上游版本事件（预测修订/财务重述/原文更正） | **终态**，衔接 N9.1-33 三类版本事件 |

- **与 `version_kind` 三类版本事件的衔接**：预测修订/财务重述/原文更正 → 触发被影响主张 `superseded` → 所有依赖结论入复查队列（N6.3-11/N6.3-18，承接 N9.1-25 引用证据版本、N9.1-33 版本不可覆盖）。
- **终态**：`superseded` 为终态；`refuted` 可被"反证撤回"重新打开。
- **触发者**：程序（口径/计数/依赖传播）+ 人工（关键裁决）+ 第 7 步规则（状态机）。

#### (g) 为什么专门写"官方确认不是硬门槛"

- **现实原因**：重要信号（订单、供货、合作）官方常长期不披露；若设为闸门，会系统性漏掉早期、可复核的第三方证据——与第二章"允许在经营结果完全兑现前提出买入建议""官方确认不是必要条件"一致。
- **对证据闸门设计的意义**：闸门判据 = **证据质量（可信+独立+可复核）**，而非"来源等级==官方"。官方确认只能作为**提高置信的非门控项**，不能作为否决项。→ 直接支撑 T04。

#### (h) 被禁止的实现做法（≥5 条）与被允许的替代

**禁止**：
1. 给来源/平台设固定权重系数并对证据加权求和。
2. 用文章数量/转载量决定证据强度。
3. 用情绪/热度/粉丝量投票决定买卖。
4. 用模型自评的可信度分数直接加权证据或裁决状态。
5. 把"来源等级"当硬门槛（非官方即否决）。
6. 对一手/KOL 预设固定分数（原文明确禁止）。

**允许的替代**：三维分离（顺序/相信/深度）；证据质量按可复核维度逐项标注 + 独立佐证计数；人工核验样本作质量基准；官方确认作非门控提高置信项；重要性驱动核验投入。

#### (i) 事实可信度 / 模型推断可信度 / 未来经营兑现确定性 三分

| 概念 | 落到 | 字段/对象 |
|---|---|---|
| 事实可信度 | 针对"已发生事实" | `claim_quality` + `claim_status` |
| 模型推断可信度 | 估值/独立判断的假设 | 估值对象上的 `assumption_confidence`（模型估计 vs 人工设定分开，N9.1-21） |
| 未来经营兑现确定性 | 增长确定性 | 研究基线的 `realization_certainty`（N9.1-18 价值状态） |

**为什么合并会出错**：三者是不同对象、不同失败模式。合并会把"事实很硬"误当"预测很确定"（第四章明确"经营事实可信≠未来增长必然兑现"），或把"模型不确定"误当"事实不可信"而错误否决。

### 2.4 关于 6.4 缺失处理

| 情形 | 触发条件 | 系统行为 | 展示行为 | 数据字段 | 衔接需求ID |
|---|---|---|---|---|---|
| 无订单金额/份额 | 主张涉经济暴露但未披露 | 存 `UNKNOWN`，不填猜测值 | 标"未披露" | `relation.economic_exposure=UNKNOWN` | N9.1-09 |
| 只有研报摘要/少量预测 | `obtainable_content_type=summary` 或 `sample_n` 小 | 记取得范围与样本数，不称一致预期 | 标"公开预测样本(n=x)" | `forecast_sample.sample_n`、`coverage_note` | N9.1-20 |
| 视频无字幕 | 无法解析正文 | 保留任务+入口，状态=未解析 | 标"尚未完成解析" | `source.obtainable_content_type=no_transcript`、`task=pending` | N9.1-10 / N9.1-11 |
| 只有延迟行情 | 行情源为延迟 | 显示时间+延迟，不标实时 | 标"延迟" | `snapshot.delay_flag`、`as_of_time` | N9.3-04 / N9.1-19 |
| 关键材料/估值输入缺失 | 缺失阻塞某步骤 | 保留已完成，明确缺口步骤 | 标"不足以完成X" | `gap` 记录对象 | N9.1-21 |

**"必要时输出待判断"是同一个状态吗？**
- **第六章语境**：证据/输入不足 → 输出"待判断/研究未完成"（缺口在**证据层**）。
- **第二章语境**："暂时无法判断是否跑赢基准" → 待判断（缺口在**相对收益判断层**）。
- **结论**：**共享同一顶层展示态"待判断"，但来源不同**——前者是"证据不足"，后者是"相对收益无法判断"。二者 underlying 缺口对象不同（证据缺口 vs 判断缺口）。**关键约束**：第六章的"证据不足待判断"**不得**被自动升级为第二章的"预计跑不赢→卖出"（N6.4-06 + 第二章"不能自动变成卖出"）。

## 3. 冲突与张力清单

| 张力编号 | 涉及原文两方 | 冲突描述 | 裁决建议 |
|---|---|---|---|
| C6-1 | 6.2「不按平台划分」 vs 系统需要可执行自动化规则 | 平台是最易自动判定的特征，但被明令排除为分级主依据 | 裁决：分级主键用 `publisher_entity`（主体身份），平台仅作辅助特征。需维护"官方账号/机构账号"名录（可自动化判定主体类型）；对无法识别主体的来源降级为待核验，不用平台兜底。 |
| C6-2 | 6.2「不按系统自行判断的法律责任划分」 vs N9.2-01 对外部文本做安全处理 | 一个禁止系统自判责任，一个要求系统处理外部文本风险 | 裁决：二者不冲突但需划界——**分级**不得引用"法律责任"自判（只按事实最初出处主体类型）；**安全处理**（注入防护、隔离）是工程侧对"内容"的处理，不进入分级字段。分级≠安全等级。 |
| C6-3 | 6.3「不预设固定分数加权」 vs 第 3 步"转述不增独立证据数量"本质是一种加权判定 | 独立/转述判定听起来就是给证据加权 | 裁决：区分"**预设来源等级固定系数**"（禁止）与"**基于关系的等价判定**"（允许）。转述判定依据 `origin_claim_id` 同源事实，是**去重**而非**打分**；独立计数是**基数**而非**权重**。禁止的是给一手/KOL 预设分数。 |
| C6-4 | 6.3「研究增量重复则归档」 vs 第八章"必须保留可追溯历史" | 归档是否等于删除？ | 裁决：**归档 ≠ 删除**。归档=退出活跃队列（不触发更新、不入建议证据集），但保留记录与引用链、可 as-of 回溯。归档标志与保留策略分离（N6.3-07 + N9.1-33）。 |
| C6-5 | 6.3「重要且不确定优先核验」 vs 第 6 步"预算到限保留待核验" | 重要性要求深挖，预算要求停手 | 裁决：**重要性决定是否入核验队列与投入上限，预算决定单次核验的停止点**。到限即转待核验并保留可重入任务（不丢弃、不伪装完成）。优先级排序仍按重要性，预算只控制"单轮深度"。 |
| C6-6 | 6.4「视频无字幕显示尚未完成解析」 vs 第八章"未完成核验可见" | 是同一状态还是两级？ | 裁决：**两级**。①"尚未完成解析"=采集/解析层任务（无字幕，尚未进入主张化）；②"未完成核验"=主张层任务（已出主张、待核验）。二者共享"未完成可见"的展示原则，但 underlying 任务类型不同，不可合并。 |
| C6-7 | 6.1「未授权新增付费数据订阅」 vs 第五章要求研究外部预期 | 公开预测样本不足时怎么办 | 裁决：**降级而非采购**。样本不足时用 N6.4-02 标注"公开预测样本(n=x)"并披露覆盖缺口；允许公开渠道补充；**不得**引入未授权付费预期库。缺口本身作为待判断/复查依据（第五章"必须披露覆盖缺口"）。 |

## 4. 最小可用数据集（按第十一章 5 阶段）

**阶段 1 需求与来源准备（本章 P0 必须就位，否则无法产"公开数据登记"）**
- `Source` 登记：访问方式 / 更新时间 / 可提取字段 / 采集限制 / 失败处理 → 与 N9.3-01~07 对齐（**缺则无法产"公开数据登记"**）
- `Claim` 最小集：主体 / 指标 / 期间 / 单位 / `claim_nature` / `locator` / `origin_claim_id`（**缺则无法主张化**）
- `ClaimPropagation` 表（**缺则 T01 无法通过**）
- 分级字段：`publisher_type` / `tier` / 判定依据（**缺则三维排序无法建立**）
- `obtainable_content_type` + `full_text_read` 约束（**缺则 N6.1-11 无法强制**）

**阶段 2 NVIDIA 深度样例**
- `ClaimQuality` 六维（至少 `caliber_match` 程序化）→ 支撑证据与推导可检查
- `ClaimImpact`（映射驱动/条件/护城河/预期）→ 支撑研究增量

**阶段 3 核心产业链运行**
- `Claim.status` 五态状态机（**缺则 T03/T04 无语义承载**）
- `VerificationTask`（含预算闸门行为）（**缺则第 6 步不可验收**）
- 独立证据计数（**缺则 T01 失败**）

**阶段 4 每日持续研究**
- 版本事件 → `superseded` 传播 + 依赖复查（**缺则 T12 失败**）
- 缺失处理五情形字段（**缺则连续运行中缺口不可见**）

**阶段 5 覆盖扩展与评估**
- 来源质量/作者表现（人工核验样本为基准）→ 支撑 T02 与质量复盘
- 归档标志 + 保留策略（**缺则研究标准一致性不可核验**）

## 6. 给架构师的交接要点

实现方案必须优先解决以下 6 点，否则第六章不可验收：
1. **三维正交不得合并成单一分数**——`tier`（顺序）/ `claim_quality`（六维可信）/ `claim_impact`（重要性）三组字段独立建模；决策函数中不得出现固定分数加权、数量/情绪投票（N6.3-12/13/14）。
2. **分级主键是"主体身份 + 事实最初出处"，不是平台**——需 `publisher_entity` 名录与 `origin_claim_id` 引用链；三个反例各对应一条可执行规则（N6.2-08/09/10/11/12）。
3. **`claim_propagation` + `independent_evidence_count`**——独立 vs 转述的判定规则（指纹相同 + 共同上游=转述；直接知情 + 无共同上游=独立）必须先落，否则 T01 无法通过。
4. **`full_text_read` 强制校验**——`obtainable_content_type` 约束 `claim.locator` 上限，越界由程序拦截（非模型自觉），展示层自动标注"仅摘要"（N6.1-11）。
5. **五态状态机 + 依赖传播**——`supported/disputed/pending_verification/refuted/superseded` 流转规则；三类版本事件（预测修订/财务重述/原文更正）→ `superseded` → 依赖结论入复查，与 N9.1-33/N9.1-25 对齐（N6.3-10/11/18）。
6. **预算闸门 = 转待核验 + 可重入任务**——到限不丢弃、不伪装完成；缺省行为必须可验收（N6.3-09）。
