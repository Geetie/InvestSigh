## A. 本章定位与实现总览

第二章把 14 条投资规则翻译为**可自动检查的约束**，核心是三件事：

```
① 禁止项自动扫描（P-01~P-10）  ←  本章最核心落地物
② 字段补齐（opportunity_types[] / moat_level）  ←  含硬冲突 A-02 修复
③ 前置门强制（提前判断三要素 / horizon 区间 / 反拖延）  ←  含硬冲突 A-06 修复
        ↓
四类检查机制：schema断言 · AST/配置扫描 · 决策输入结构断言 · 展示规则检查
        ↓
统一由「冲突扫描器 conflict_scan」在 4 个时机自动运行（§B.3）
```

**关键设计判断**：
- **为什么不用运行时"检查报告"而用"断言/门"**？因为第二章条款是**首版硬验收**，"提示后可忽略"等于没有条款。故：字段级 → `schema.assert_*`；函数/配置级 → AST 扫描**不过即 fail**；决策级 → gate 输入结构断言。
- **为什么"排序 ≠ 门槛"**（C123-4）？排序是**处理顺序**（Ch6 `priority_order` 字典序），**不拒绝任何建议**；门槛是"能否出建议"。二者作用环节不同，本章在 §B.2 明确"排序环节允许、判定环节禁止"。

## B. 禁止项 P-01~P-10 自动化检查设计（核心）

### B.1 检查口径（五层）

| 层 | 检查方式 | 覆盖禁止项 |
|---|---|---|
| L1 schema 字段存在性断言 | `schema.assert_absent(fields)` / `assert_present(fields)`；**作用域**：断言对象是 **`Recommendation` 对象的 `properties` 字段名集合**，**非全仓 token 扫描**（见下方「★ 禁词作用域通则」） | P-03 P-04 P-05 P-07 |
| L2 AST + 禁词表扫描 | 解析 `scripts/**/*.py`，命中禁词即 fail；**P-09 例外**：`weight`/`score` 等通用词仅在**决策函数**内触发（scope 见 §B.3 Checker-1） | P-01 P-02 P-09 |
| L3 配置扫描 | 遍历 `rules/**/*.{yaml,json}` 键名/值 | P-01 P-02 |
| L4 决策函数输入结构断言 | 对 gate 的输入 dataclass 做字段集合断言 | P-06 |
| L5 展示层渲染规则检查 | 渲染配置/组件排序·颜色·折叠策略断言 | P-10 |

> **★ 禁词作用域通则（P-09 / P-04 同族，通用于全部禁词）**：
> 1. **入库前必查同名**：任一禁词写入 `rules/banned_tokens.yaml` 之前，**必须先在包内 `grep` 该 token**，确认是否存在**合法同名用途**（不同语义、不同域的同拼写 token）。
> 2. **有同名必须声明 `scope`**：若存在**合法同名用途**，该 token **必须**声明 **token 级 `scope`**（落 `rules/banned_tokens.yaml`，随 BANNED_TOKENS 一同版本化 + SHA256 锁）；**无 `scope` 不得入库**（否则在全仓扫描下必与合法同名词碰撞，而本包定「命中即 fail、禁 warn-only」，一次误报即卡死发布流程）。
> 3. **scope 必须可执行**：scope 判定必须是**函数级 / 对象级**的**可执行断言**（如"仅在决策函数内生效""仅对 `Recommendation` 字段名生效"），**不得写成"人工注意"**之类不可检查的措辞。
> 4. **本通则的两次实例**：**P-09**（`weight`/`score`/`vote`/`sentiment`/`follower_count` —— 合法同名的大量普通变量，scope = 仅决策函数内，见 §B.3 Checker-1）；**P-04**（裸词 `position` —— 合法同名词 `position_listed`/`business_positions` 表示"产业链位置"语义，scope = 仅 `Recommendation` 字段名，见 §B.3 Checker-2）。**两次修复只做"消歧"，不新增禁止项、不放松约束**。

### B.3 检查器伪代码（≥3 个，给出 5 个）

> 均为语言无关伪代码，工程师可落地为 Python。**核心约束：命中即 fail（非零退出码），禁止 warn-only。**

```python
# ── Checker-1：AST + 禁词表扫描（覆盖 P-01 / P-02 / P-09）────────────
# scope（★设计约束，消歧 P-09 误报）：P-01/P-02 为**全局**扫描；P-09 的通用词
#   （weight/score/vote/sentiment/follower_count）**仅在决策函数内**命中才 fail——
#   否则业务代码里的普通 "score/weight" 变量会误报，在"命中即 fail、禁 warn-only"
#   下形成死锁。判定"是否决策函数"= 位于 decision/gate 模块或 classify_*/assert_*
#   调用链（对应 §B.2 P-09"进入决策函数"的口径）。
BANNED_TOKENS = load_yaml("rules/banned_tokens.yaml")  # 只读、版本化、SHA256 锁
SCOPED_TOKENS = {"weight", "score", "vote", "sentiment", "follower_count"}  # 仅决策函数内生效

def scan_ast(root: str = "scripts") -> list[Violation]:
    violations = []
    for path in walk_py(root):
        tree = ast.parse(read(path))
        in_decision = is_decision_scope(path)          # scope 判定，见上方 ★设计约束
        for node in ast.walk(tree):
            # 变量名 / 函数名 / 属性名 / 字符串字面量 全量比对禁词
            for name in names_and_strings(node):
                tok = normalize(name)
                if tok in BANNED_TOKENS:
                    if tok in SCOPED_TOKENS and not in_decision:
                        continue                        # P-09 通用词：非决策函数内不触发
                    violations.append(Violation(
                        rule=map_to_rule(name), file=path, node=node.lineno,
                        severity="FATAL"))
    return violations        # 非空 → 进程 exit(1)
```

```python
# ── Checker-2：schema 字段存在性断言（覆盖 P-03 / P-04 / P-05 / P-07）──
# ★ 作用域声明（P-04 消歧，对齐 §B.2「★ 禁词作用域通则」）：
#   本 Checker 的断言对象 `rec` **已被限定为** `schema["defs"]["Recommendation"]["properties"]`
#   ——即**仅该对象的字段名集合**。**禁止实现者把它扩展成全仓 token 遍历**：
#   `assert_absent(rec, ...)` 只对 `Recommendation` 的字段名生效，**不得**改成对
#   `scripts/**` 或全包文本做裸词 `position` 扫描。
#   反例（合法同名词，**不得误报**）：
#     · `position_listed`（"产业链位置"收录态，见 03 §需求拆解 N3.2-04 / 03 §实现方案 C.2）
#     · `business_positions`（公司×节点多业务位置数据对象，见 09 §2.1.3 / §3.3.3）
#   裸词 `position` 的禁止语义 = "建议对象上不得出现仓位/持仓/成本类字段"，
#   与"产业链位置"语义**无关**；朴素全仓正则会在 `position_listed` 上误报并卡死流程。
def assert_schema(schema: dict) -> None:
    rec = schema["defs"]["Recommendation"]["properties"]   # 作用域边界：仅此字段名集合
    # 必须"不存在"的字段（禁止项）
    assert_absent(rec, ["stop_loss", "stop_price",
                        "quantity", "position", "shares_held",
                        "cost_basis", "portfolio_weight",
                        "consensus", "market_view", "average_forecast"])
    # action 枚举不得含做空
    assert set(rec["action"]["enum"]) == {"buy", "sell", "pending", "maintain"}
    # 必须"存在"的字段（本章修复项，见 §C）
    assert_present(rec, ["opportunity_types", "horizon", "start_date"])
```

### C.2 【必要区分修复】护城河"水平"字段（N2.2-02）

**问题**：仅有 `moat_state`（趋势），缺"水平"字段。
**修复（落 Ch4）**：

| 字段 | 取值 | 语义 |
|---|---|---|
| `moat_level`（**新增**） | `weak / moderate / strong / tbd` | 护城河**水平**（整体强弱） |
| `moat_state`（既有） | `strengthening / weakening / unchanged / tbd` | 护城河**趋势**（变化方向） |

> 两字段**独立**、可同时出现且不同向（对齐 N2.2-04 三维不同向）。断言：二者不得合并为单一 `moat` 字段。

> **待定 token 规范（v1.1 回改 F-10 / R-14）**：包内所有"待定 / 未确定"**枚举值**统一为小写 **`tbd`**；历史拼写 **`tdb`**（字母颠倒）与长式 **`to_be_determined`** **已归一，不得再用**。适用字段：`moat_level`、`moat_state`、`growth_momentum_state`、`certainty_state` 等一切"待定"取值。**中文散文里的"待定"叙述不受此约束**（仅约束枚举 token）。

> **命名规范（v1.1 回改 R-15~R-21，与"待定 token 规范"并列）**：
> ① **枚举取值一律小写 + 下划线**（`snake_case`），**禁止中文取值**（中文 token 做 `==` 等值判断，一旦同义词写歪即静默不等，review 也看不出）。历史中文取值已归一：`direct_knowledge → {direct, indirect, unknown}`、`price_gap_state → {fully_reflected, not_fully_reflected, attractive}`。
> ② **同名不同域必须消歧**：来源分级保留 `tier`，数据源 allowlist 改用 **`license_tier`**；`driver.realization_stage` 与 `relations.relation_progress_stage` **分别命名、不得互用**。
> ③ **一个概念只允许一个字段名**：禁止 `obtainable` / `obtainable_content_type` 并存（已统一为 `obtainable_content_type`）。
> ④ **留痕规范（R-23）**：**文件头版本行只写「概括 + 指针」，不再逐条枚举 R 编号**（枚举每回改一次即漂移、会触发反复追改；指针不会）；所有改动明细以各文件文末「回改记录」为**唯一权威**。本规范自 R-23 起适用全包。

### D.1 【硬冲突 A-06 修复】提前判断三要素 = 买入前置必填（规则 6 / N2.1-06）

def assert_early_judgment_complete(rec) -> None:
    trio = {
        "assumptions": rec.assumptions,
        "evidence_gaps": rec.evidence_gaps,
        "verification_conditions": rec.verification_conditions,
    }
    for name, val in trio.items():

### D.3 反拖延检测（N2.2-05 / C123-6，需补充）

```python
def detect_horizon_extension(chain: list[Rec], N: int) -> list[Flag]:
    flags = []
    ext = 0
    for prev, cur in pairwise(chain):
        if cur.horizon > prev.horizon:               # 期限被延长
            ext += 1
            if ext >= N:                             # ① 连续延长 ≥ N 次
                flags.append("horizon_extension_suspicious")
            if days_before(cur.written_at, cur.review_date) <= 3:  # ② 临近复查日
                flags.append("horizon_extension_suspicious")
            if cur.assumption_changed is False:      # ③ 未更新假设
                flags.append("horizon_extension_suspicious")
        else:
            ext = 0                                   # 有缩短则重置
    # ④ 触发即转人工复核 + 记 vision_drift，不得静默延期
    return flags
```
