# 第二章《已确认的投资规则》逐节需求拆解

> 分析对象：`02_可编辑源稿_v2.md` 第二章（第 31–58 行）。沿用已验证六段式范式。
> **章性质**：第二章是**硬约束层（最高优先级）**。它的产物不是"实现什么功能"，而是**"实现时必须满足什么、绝对不允许出现什么"**——即**禁止项清单 + 可自动检查的约束**。
> 原文红线（第 33 行）：**"技术实现、信息筛选和页面设计不得悄悄增设与这些约定冲突的买卖条件。"** 这是覆盖**所有层（含 UI）**的全局禁止条款。
> 三条主线：① **买/卖条件只来自本章，不得增设**；② **多个"必要区分"必须落成独立字段**；③ **禁止项要能自动扫描**。

### 2.4 四组必要区分逐组落地

| 组 | 落地 | 关键点 |
|---|---|---|

| **反拖延**（不靠延长期限掩盖未兑现） | **可测规则**（见下） | ⚠️ 当前无检测（见扫描 A-20） |

**反拖延的可测规则**：
1. 同一`recommendation_id`链上 `horizon` 被**连续延长 ≥ N 次**（N 待冻结，建议 2）→ 标 `horizon_extension_suspicious`。
2. 每次延期若发生在**临近 `review_date` 时**（如复查日前 3 天）→ 额外标可疑。
3. 延期的同时**未更新假设**（`assumption_changed=false`）→ 标可疑。
4. 触发：转人工复核 + 记录 `vision_drift`（愿景漂移）标记，**不得静默延期**。

### 2.5 全局禁止条款（含页面设计）如何强制

- **机制**：规则版本 + 变更审计——任何影响买卖条件的改动（含展示逻辑）必须走**规则版本变更**并留痕；`rules/` 只读、模型不可写（承 N9.2-01 / N9.1-25）；建议绑定当时规则版本。
- **为什么包括页面设计**：展示方式本身可形成**隐性买卖引导**。例如：
  1. 每日页**默认按"买入建议"置顶排序** → 暗示买入优先；
  2. 用**红涨绿跌/紧迫色**暗示"现在就买/快卖"；
  3. **隐藏或弱化反证/缺口** → 只展示支持证据；
  4. 用**"强烈推荐/机会难得"**等营销性措辞。
  → 这些都等于**悄悄增设了买卖条件/倾向**，违反 N2.3-01。
- **检查**：展示层渲染规则需断言"排序/颜色/折叠不得改变信息中性；反证与缺口必须与支持证据同等可见"（扫描 A-21）。

## 3. 冲突与张力清单（C123）

| 编号 | 涉及两方 | 冲突描述 | 裁决建议 |
|---|---|---|---|
| C123-1 | 第一章「任何缺口应能转为研究任务」 vs 第六章预算闸门 | 缺口无限、预算有限 | **入队无限、执行受限**：缺口→任务可无限入队，执行受 `research_cap`；到限转 `pending_verification` + 保留可重入任务 |

| C123-5 | N2.3-02「不另设固定置信度门槛」 vs 第七章前置门"可解释预测" | 是否变相置信度门槛 | **不是**：前置门校验的是**结构完备性**（有假设+期限+收益+DerivedValue底稿），**不是置信度数值阈值**；门槛是"有无可解释的预测"，非"置信度≥X"。须确认 gate 不含任何置信度数值比较 |

| C123-7 | N2.3-01「不得悄悄增设条件（含页面设计）」 vs 第八章"每日页展示建议变化" | 展示即可能隐性引导 | **展示须中性**：展示变化可以，但排序/颜色/折叠不得形成买卖倾向；反证与缺口同等可见 |
| C123-8 | 第三章「不按数量凑名单」 vs 交付计划需规模 | 质量 vs 估算 | **以核验门槛定规模**：先按可核实关系出名单，再据实际名单估工作量；**不为凑交付规模降门槛** |

| C123-10 | 第三章「不另建跨资产模块」 vs 环境层需利率等宏观数据 | 环境层 vs 不建模块 | **环境因素入公司与基准研究**（作假设域/证据），**不建独立宏观/跨资产模块**；用边界检查防膨胀 |
| C123-11 | 第三章「非美证券待定」 vs 附录一含 ASML/TSM/SK hynix 等关键上游 | 不纳入则缺关键上游 | **待定项须显式**（`non_us_in_scope=pending`），不得静默默认"只做美股"；提示：若不纳入，首批将缺光刻/代工/存储关键上游（见 03 文件 §2.4） |
| C123-12 | 第三章「基准不因表现好坏更换」 vs 第十一章"代码确认时冻结" | 冻结前是否算变更 | **冻结前 = 定稿流程（非性能驱动变更）**；冻结后任何变更须记生效日期 + 保留旧口径 + 理由审批。区分"定稿"与"因表现更换" |
