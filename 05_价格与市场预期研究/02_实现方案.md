## B. 反向检验的实现 ★

### B.1 数学形式（欠定 → 必然多解）

价格 `P = f(g, m, r, k, T)`（增长 g、利润 m、再投资 r、风险 k、持续时间 T）是**欠定方程**——一个 P 对应**无穷多组**解。故**必须展示多组解**，否则会把某一解误当"市场的唯一真相"。

### B.2 多组解的输出结构（`facts/implied_requirements.jsonl`）

```json
{"implied_id":"IMP-001","solution_set_id":"SET-nvda-2026-09-15",
 "security_id":"sec_nvda","price_snapshot_id":"SNP-...","current_price":"...",
 "assumptions":{"growth":{...},"margin":{...},"reinvestment":{...},
                "risk":{...},"duration":{...}},
 "solved_variable":"reinvestment",                    // 固定其余 4 类，解第 5 类
 "range":{"low":"...","high":"..."},                  // 区间表达
 "alternative_explanations":["...","..."],            // 替代解释
 "feasible":true,"method_version":"v1","computed_at":"..."}
```

- `solution_set_id` 聚合一组解；展示层呈现"使当前价格成立的**解集**"（多组 + 每组区间 + 替代解释）。

### B.3 模型与程序的界面分工（模型不做算术，程序不做假设）

| 责任 | 谁 | 内容 |
|---|---|---|
| 假设生成 | **模型** | 候选假设（g/m/r/k/T）取值与组合方向、替代解释、**假设空间边界** |
| 求解 | **程序** | 固定 4 类解第 5 类；由假设正算隐含价格；迭代找可行解集（`scripts/pricelayer/solver.py`） |
| 校验 | **程序 + 人工/规则** | 程序校验口径与算术（N9.2-03）；人工/规则校验假设合理性 |

### B.4 假设组合表结构

| 假设类 | 字段 | 取值方式 |
|---|---|---|
| 增长 g | `growth_assumption` | 收入 CAGR / 终值增长（点或区间） |
| 利润 m | `margin_assumption` | 利润率（点或区间） |
| 再投资 r | `reinvestment_assumption` | capex/收入、ROIIC |
| 风险 k | `risk_assumption` | WACC / 折现率 |
| 持续时间 T | `duration_assumption` | 高增长持续年数 |

**组合方式**：反解时固定 4 类、解第 5 类；每组带区间，形成"解集"。

### B.5 为什么反解不能直接作 baseline 输入（程序约束）

> **裁决 C45-1：反解 = 诊断（不产建议），正估 = 定价（先 baseline 后估值）。**

```python
# scripts/pricelayer/order_guard.py（可测）
FORBIDDEN_BASELINE_SOURCES = {"implied_solution", "implied_requirements"}

def assert_baseline_source_ok(assumption):
    if assumption.source in FORBIDDEN_BASELINE_SOURCES:
        raise OrderViolation("反解输出不可直接作 baseline 输入（仅作研究线索）")
```
- **单测**：构造一个 `source=implied_solution` 的假设写入 `baselines.driver_model` → 断言被 `OrderViolation` 拒绝；反解输出只允许写 `implied_requirements` 或 `gap`。

## C. 三份判断分开存 ★

### C.1 三份判断的 schema / 来源 / 可信度 / 更新频率

| 判断 | 存储 | 来源 | 可信度标签 | 更新频率 |
|---|---|---|---|---|
| 外部预期 `expectation` | `facts/expectations.jsonl`（N9.1-20） | 公司指引/券商/社交（**各自身份**） | 按来源分级（第六章） | 跟来源更新 |
| 价格隐含 `implied` | `facts/implied_requirements.jsonl` | 反向估值计算 | 依赖假设合理性 | 每次价格/假设变化 |
| 独立判断 `independent` | `baselines.valuation.independent_judgment` | 第四章 baseline + 估值 | 研究深度 + 方法版本 | 随 baseline 更新 |

三者差异 → `gap`（`type=price_vs_independent`），供第七章"待判断"输入。

### C.2 禁止合并成"市场认为"的程序约束（可直接写单测）

| 断言 | 内容 |
|---|---|
| C1 | schema 中**不存在** `consensus` / `market_view` / `average_forecast` 等聚合字段：`assert not any(f in EXPECTATION_FIELDS for f in {"consensus","market_view","aggregated","average_forecast"})` |
| C2 | `expectations` 每条必须有 `source_id` + `provider` 身份（非空），否则校验失败 |
| C3 | 展示层 `views/` 渲染函数**只允许按 `provider` 分组**，禁止产出无来源聚合项（渲染器拒绝无 `source_id` 的预测行） |

**违反做法（≥3）**：① 券商预测取平均去掉来源；② 社交讨论并入"市场预期"；③ 公司指引替代外部预期；④ 三份判断合成"共识价"。
**允许**：分别带来源展示；可按来源聚合但**保留每个来源身份**。

## D. 估值与防倒推 ★

### D.1 估值方法按商业模式路由

`rules/valuation-methods.yaml`：`method_class → business.model_class` 绑定（复用第四章 C 的路由思路）：

| `model_class` | `method_class` |
|---|---|
| hardware | 正常化利润 / 含再投资现金流 / 分部估值 / 同行比较 |
| cloud | 含再投资现金流（订阅/用量） + 分部 |
| software | 正常化利润 / 现金流 + 留存指标 |
| ETF（基准） | 简化底稿（E） |

方法注册表驱动；未注册类型归入 generic 并标注。

### D.2 可追溯链字段设计（完整例子）

```python
DerivedValue(
  value="...", formula="...", operands=[...], method_version="val-v1",
  inputs={"forecast_assumptions": [...],    # 来自第四章 drivers
          "valuation_params": [...],        # 方法参数（模型估计/人工设定）
          "share_count": "...",             # 股本
          "compute_date": "..."})           # 计算日期
```
**例子**：`baseline.drivers[GPU 出货量] → 分部收入 → 净利 → EPS`（第四章）→ 估值参数（增长率/WACC）→ **每股价区间** `DerivedValue{formula, operands, share_count, compute_date}`。每个 price range → formula + operands + method_version + share_count + compute_date（N5.3-02 / N9.2-02）。

### D.3 顺序约束的程序化

```python
# scripts/pricelayer/valuation.py（可测）
def compute_valuation(baseline_version, params, *, compute_time):
    assert baseline_version.system_time.analyzed_at < compute_time, \
        "估值计算时间必须晚于 baseline 版本时间（禁止倒填）"
    ...
```
- **单测**：`baseline_version` 时间晚于 `compute_time` → 断言 `OrderViolation`。

### D.4 倒填检测四条规则 + 单测

| 规则 | 判定 | 处置 | 单测 |
|---|---|---|---|
| 参数后改 | `valuation_param.modified_at > recommendation.issued_at` | 标可疑 → 复核 | 构造参数后改 → 断言 `suspicious=true` |
| 临界凑值 | 结论对某参数高度敏感且参数被调到刚好跨阈值 | 标可疑，要求敏感性披露 | 构造临界参数 → 断言要求敏感性 |
| 无历史假设 | `assumption_source=manual` 且无变更记录 | 标可疑 | 构造无留痕 manual → 断言可疑 |
| 版本倒序 | baseline 版本时间晚于估值时间 | **拒绝** | 断言 `OrderViolation` |

### D.5 事实输入 / 模型估计 / 人工设定三类分开存

- `input_source ∈ {fact, model_estimate, manual}`；`fact`=来自 `claim` 的原始数据；`model_estimate`=模型产出假设；`manual`=人工设定。
- **谁有权写 manual**：授权用户（需求方/研究员），须留痕（`author` + `modified_at`）（N5.3-04）。
- **冲突处理**：**不用加权**（承第六章禁加权、C45-4）——分别保留并**并列展示**，冲突时标 `conflict_status="unresolved"`。

> **【v1.1 回改 R-09】** 环境层"**利率与折现要求**"作为**估值假设输入**注入：`risk_assumption`（WACC / 折现率）以 `input_source ∈ {model_estimate, manual}` 存（第三章 N3.3-01）。环境项仅作输入，**不独立成模块**（Ch3 模块 denylist）。

### D.6 区间宽度表达 + 概率字段默认 null

- 区间用 `range{low, high}` 表达宽度；**不把宽泛区间包装成精确预测**（N5.3-06）。
- **情景概率默认 `null`**（不默认 50/50）：`probability: null`；仅当有依据才填（N5.3-07 / C45-2）。

```python

assert "probability" not in required_fields                # 非必填
```

## E. AGIX 基准的特殊处理 ★

### E.1 ETF 特殊问题 → 字段

| 问题 | 字段（`benchmarks` 新增） |
|---|---|
| 非上市资产无法独立建模 | `non_listed_assets{value, weight, gap_note}` |
| 公开持仓披露延迟 | `holdings_disclosure_lag` |

### E.2 "用历史外推未来"的程序检测

```python
# scripts/pricelayer/history_guard.py（可测）
def is_historical_extrapolation(forecast):
    if "past_return" in forecast.basis or forecast.basis == "trailing_return":
        return True                                    # 用历史涨幅
    if forecast.period != forecast.evidence_period:    # 用历史期推未来期
        return True
    return False
```
- **违规即拒绝**（N5.4-04）：`forecast.basis` 引用 `past_return`，或 `forecast.period` 与证据期间不匹配 → 拒绝。预期收益必须来自 forward assumptions；历史仅作诊断。
- **单测**：构造 `basis="past_return"` → 断言 `is_historical_extrapolation=True` 且估值拒绝生成。

### E.3 情景口径一致性检查（可直接写单测）

```python
# scripts/pricelayer/scenario_guard.py（可测）
def assert_scenario_match(stock, benchmark):
    if stock.scenario_tag != benchmark.scenario_tag:
        raise ScenarioMismatch(stock.scenario_tag, benchmark.scenario_tag)  # 拒绝生成相对判断
    return True
```
- **单测**：个股乐观 + 基准悲观 → 断言 `ScenarioMismatch`（N5.4-08）——**不能比较个股乐观情景与基准悲观情景**。

### E.4 `scenario_method_status = pending` 的落地

```yaml
scenario_method_status: pending | neutral | probability_weighted    # 默认 pending
```
- 首版方法（中性情景 vs 概率加权）未定 → **显式 `pending`，不静默默认**（N5.4-07 / C45-2）。
- **对下游（第七章收益比较）的阻塞行为**：`scenario_method_status=pending` 时，`assert_scenario_match` 无法建立一致口径 → **阻塞相对判断生成**（第七章前置门收不到可用的 `benchmark_forecast`，输出"待判断"而非建议）。
- **待定转正流程**：样例确定后 → 写 `rules/scenario.yaml`（版本化）→ `status` 转 `neutral`/`probability_weighted` + 记 `method_version`。

### E.5 未建模部分覆盖率（不声称完整预测）

`benchmarks.modeled_coverage` + `unmodeled_parts[]`：未建模部分**显式标注**；`modeled_coverage < 1` 时不得声称"完成整个基金预测"（N5.4-05）。

### E.6 【v1.1 回改 R-06 / R-10】价格缺口状态 + 基准收益守卫

**R-06 价格缺口状态 `price_gap_state`（供机会分类）**——第五章向第七章 `classify_opportunity()` 显式暴露"独立判断 vs 价格隐含"的缺口（此前仅为内部计算）：

| 字段 | 取值 | 语义 |
|---|---|---|
| `price_gap_state` | `fully_reflected` / `not_fully_reflected` / `attractive` | 独立判断相对价格隐含要求的缺口档 |

- 判定：`implied`（价格隐含）vs `independent`（独立判断）之差 → 归档 `price_gap_state`。
- A 类机会需 `price_gap_state=not_fully_reflected`；B 类需 `price_gap_state=attractive`（与第七章 §E.3、第二章 §C.1 一致）。
- **诊断用途，不作买卖门槛**（C123-4）；不得据此单独触发买入（仍走第七章收益比较）。

**R-10 基准收益守卫**（承第三章 N3.4-05/07）——`benchmarks` 收益一律经 `scripts/benchmark/return_guard.py`：① 取**基金本身**行情，**禁用替代指数**；② 相对收益**禁止二次扣费**，净值仅标 `diagnostic`。

## F. 每日价格解释

### F.1 先做行情口径校验

```python
# scripts/pricelayer/daily_explain.py
def validate_quote(snapshot):    # T11 / N5.5-01
    check(snapshot.quote_time, snapshot.trading_session,
          snapshot.currency, snapshot.adjusted_flag, snapshot.corporate_actions_ref)
```
- 校验未通过的行情**不用于**解释与收益计算（承 N9.3-08 公司行动口径）。

### F.2 三分类（已确认 / 合理推断 / 无法解释）

| 档 | 判定标准 | 判定主体 | 字段 |
|---|---|---|---|
| 已确认解释 | 完整因果链 + 证据 | 程序（口径）+ 模型（因果）+ 人工（确认） | `explanation.confirmed[]` |
| 合理推断 | 部分证据、因果未完全确认 | 模型 + 人工 | `explanation.inferred[]` |
| 无法解释 | 无依据 | 程序 | `explanation.unexplained` |

### F.3 归因必须有因果链而非时间接近（程序约束，可单测）

```python
def attribute(move, factors):
    for f in candidate_factors(move):        # 基准/同行/公司事件/环境
        if f.event_id or f.claim_id:         # 必须引用事件/主张
            if reachable_via_transmission(f, move.security_id):   # 且经传导路径可达
                return Confirmed(f)
    return Unexplained()                     # 仅时间接近 → 无法解释/待核验
```
- **单测**：构造一个"时间接近但因果链不可达"的消息 → 断言归为 `Unexplained`（N5.5-05）。

### F.4 硬隔离：价格不得写入护城河/基本面（承 C45-5）

### I.2 计算复杂度风险（反向求解是密集项，单独评估）

| 风险 | 描述 | 控制手段 |
|---|---|---|
| **反解搜索空间** | 固定 4 类解第 5 类，每类含区间 → 组合数随离散粒度指数增长 | 限制每类假设的离散粒度 + 网格搜索上界（`rules/valuation-methods.yaml`） |
| **多解展示爆炸** | 可行解集可能很大 | 只保留**代表解 + 区间包络**（`solution_set` 上限 N，超出折叠） |
| **迭代求解开销** | 每次价格/假设变化重解 | 增量重算（仅受影响标的）+ 缓存 `price_snapshot_id`→解集 |
| **Worst-case** | `O(grid^k)`（k=假设离散点数） | 设网格上限告警；必要时用单调性剪枝/二分替代网格 |
| **历史外推/情景校验** | 轻量（O(1) 判定） | 无风险 |

### I.3 复杂度增量

| 维度 | 综合 | 理由 |
|---|---|---|
| 技术复杂度 | **高** | 反解（欠定优化）+ 估值追溯 + 倒填检测叠加 |
| 运维复杂度 | **中** | 复用同一 Automation/ops；新增仅解集缓存 |
| 数据治理复杂度 | **极高** | 三份判断分离 + 三类输入 + 情景口径 + 概率默认空 |
