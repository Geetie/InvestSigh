## 2. 深度挖掘专章（第四章）

### 2.1 赚钱机制

#### (a) 可填写的赚钱机制结构

```
business.mechanism = {
  payer: {party, segment, geographies},          // 谁付费
  offering: [product/service...],                // 靠什么赚钱
  revenue_model: enum{one_time, subscription, usage, license, hybrid},
  conversion_chain: [                            // 采购/使用 → 收入
    {stage, input, output, evidence: claim_id[]} // 每段可挂证据
  ],
  cost_structure: {main_cogs[], fixed[], ...},   // 主要成本
  capital_requirements: {capex, rnd, working_capital}
}
```
- 通用转化链路模板（四段，按商业模式实例化）：**获取 → 交付 → 使用 → 变现**。
  - 硬件：订单→排产/出货→验收→收入/回款
  - 云：签约→通电/上线→利用率→收费
  - 软件：使用→付费→续约/留存→增购
- 每段必有 `evidence`（claim_id[]），否则该段标"待补证"。

#### (b) "少量关键驱动"是多少、上限由什么决定、超限怎么办

- **建议上限：每业务 3–5 个**（上限可配置）。
- **决定因素**：① 人可维护（分析师能持续跟踪）；② 财务连接清晰（每个驱动可映射到科目）；③ 模型上下文可控（避免上下文爆炸）。
- **超限处理**：分级为 `primary_drivers(≤5)` + `secondary_watchlist`；或按经济重要性取 top-N，其余归档。
- **"财务连接"定义**：`driver → 财务报表科目 → 每股指标`，例：
  - GPU 出货量 → 数据中心分部收入 → 每股收入
  - → 毛利率/费用 → 净利润 → EPS
  - → capex/营运资金 → FCF → 每股 FCF/每股价值

#### (c) 多业务多指标集路由模型

- `Company 1..* Business`；`Business.business_type ∈ {hardware, cloud, software, ...}`；每种类型注册一套 `metric_set`。
- **混合公司防串味**：指标绑定到 `business_id`（非 `company_id`）；分部财务独立；**汇总必须在分部层完成后合并**，禁止跨业务直接引用指标。
- **三类不穷举**：`metric_set` 为**可插拔注册表**。出现第四类（广告/订阅制硬件/代工/游戏内购等）→ 注册新 metric_set + 路由规则；未注册类型归入 generic metric set 并显式标注。

#### (d) 不以收入增速代替投资回报

- **替代指标集**：ROIC、ROE、**增量资本回报率 ROIIC**、每股 FCF、经济利润（EVA）、每股价值增长。
- **收入高增长实际毁灭股东价值的机制（具体例）**：某公司靠大幅降价 + 大额 capex + 应收膨胀驱动收入高增长，若 **ROIIC < WACC**，则每多投 1 元只创造低于资金成本的回报——**增长越多，每股价值越低**（价值毁灭型增长）。故收入增速必须经 ROIIC 与现金流转化率检验。

#### (e) 五种"增长的代价"与增长质量

| 代价 | 财务科目 | 字段 |
|---|---|---|
| 降价 | 收入（单价↓）/毛利率 | `price_discount` |
| 增加资本开支 | 现金流量表投资活动/CapEx | `capex_requirement` |
| 库存 | 资产负债表存货 | `inventory_buildup` |
| 应收 | 资产负债表应收账款 | `receivables_buildup` |
| 融资 | 筹资活动/净负债 | `financing_need` |

**增长质量 = f(ROIIC vs WACC, 现金转化率, 营运资金变动, 融资依赖)**，分档：高质量（自融资、高 ROIIC）/ 中等 / 低质量（靠融资与营运资金堆增长）。**不压成单一分数**，用分档 + 分项。

### 2.2 增长确定性

#### (a) 兑现时间 vs 置信度分开（为什么合并会错）

- **反例**：驱动 A"6 个月内推出"（置信度低）与驱动 B"3 年后确定"若都记"中"，处理会错——A 需要**高频验证 + 情景**，B 可**低频跟踪 + 作长周期估值基础**。合并成"高中低"丢失这一区分。
- **取值域**：兑现时间 = 具体日期/期间或分档（≤1Q / 1–4Q / 1–3Y / >3Y）；置信度 = {high/medium/low}（**不默认给数值概率**，见第五章）。
- **四象限处理**：

| | 高置信 | 低置信 |
|---|---|---|
| **近兑现** | 近期催化剂，重点跟踪 | 高频验证、标待核验，不重度依赖 |
| **远兑现** | 长周期估值基础 | 仅作敏感性/情景，权重极低或不进基准预测 |

#### (b) 驱动三态 vs N9.1-07 vs claim_nature

| 概念 | 对象/字段 | 语义 |
|---|---|---|
| 驱动三态（已发生/计划指引预测/依赖条件） | `baseline.driver.realization_stage` | 该**驱动**处于哪一兑现阶段 |
| 合作阶段 | `relations.stage`（N9.1-07） | 该**关系**处于哪一合作阶段 |
| 主张性质 | `claim_nature`（第六章） | 该**主张**是事实/计划/预测/解释 |

**三者不是同一个东西**，需对齐：驱动的三态由支撑它的 claim_nature 推导，并以关系阶段佐证。同一驱动可含多条不同 nature 的主张，取"最实"的支持证据定 stage。

#### (c) 未盈利公司必填差异

- **未盈利必填增量**：商业模式说明、兑现路径（里程碑）、资金需求（`cash_runway`、`funding_need`）、单位经济性、达到盈亏平衡的路径。
- **盈利公司必填增量**：利润率持续性（`margin_persistence`）、现金流持续性（`fcf_persistence`）、再投资回报、股本稀释影响。
- **差异**：未盈利 → 以"能否活到兑现 + 兑现路径是否成立"为核心；盈利 → 以"利润与现金流能否持续"为核心。

### 2.3 护城河

#### (a) 六种保护对象：多选

`moat.protected_objects[] ⊆ {份额, 定价, 成本, 客户留存, 资本回报, 创新效率}`，每项带 `evidence` 与 `strength`。**多选**——一家公司可同时保护多项。

#### (b) 反误判规则（可执行）

```
single_point_insufficient = ({产品领先} alone) OR ({供给紧缺} alone) OR ({高毛利} alone)

is_durable_moat = mechanism_explained
                  AND (count of {持续份额, 定价权, 成本优势, 切换成本, 规模效应, 网络效应} evidence) >= 2
                  AND cross_generation_survival
                  AND NOT explained_by_cycle
```
- **四者区分**：
  - **持续竞争优势**：跨周期、跨代际仍保持。
  - **产品周期**：单代领先，下一代可能丢失。
  - **供需周期**：紧缺时高毛利，供给恢复即消失。
  - **经营效率改善**：成本下降来自管理/规模，未必可持续。
  - 判别方法：**看优势是否随周期/代际/供给变化而消失**。

#### (c) "真实替代方案"界定

不是竞品清单，而是**客户真的会切过去的选项**；需记录：`switching_cost`（量化/定性）、`switch_trigger`（价格/性能/供应/政策）、`evidence_of_actual_switch`（是否有人真的切过）。**切换条件** = 触发 + 成本 + 真实切换实例。

### 2.4 研究基线与增量更新

#### (a) "有内容底稿"的程序校验（反形式主义）

| 可自动校验（形式完备性） | 只能人工判断（实质质量） |
|---|---|
| 六项 section 非空且达最小字段数 | 推理是否成立 |
| 必填字段非空率 ≥ 阈值 | 假设是否合理 |
| ≥1 原始材料定位（locator） | 机制解释是否有洞察 |
| ≥1 推导（公式 + 操作数） | 竞争分析深度 |
| 跨节引用一致（驱动出现在财务连接里） | 结论可信度 |

**最低标准**：程序做"形式完备性检查"（拦截空标题/无定位/无推导），人工做"实质质量评审"。

#### (b) 缺口对象（gap）

`gap = {gap_type, scope(公司/驱动/财务/估值), blocking_step(不足以完成哪一步), required_input, status, created_at}`。
- 与第八章"未完成核验可见"：gap 驱动展示"未完成 / 不足以完成 X"。
- 与 N9.1-21 缺口：**复用同一 gap 对象**，不新建。

#### (c) 增量更新记录字段结构（复用 N9.1-33）

`baseline_version`（追加式不可变）：`{prev_version_id, new_info(claim_id[]), old_judgment, new_judgment, affected_period, supporting_evidence[], counter_evidence[], changed_by, valid_from, system_time}`。
- **直接复用** N9.1-33 追加式不可变 + 双时间轴，不新建机制。

#### (d) 3×4 状态矩阵

- **为什么必须三个独立字段**：第二章明确"动力增强、确定性减弱、护城河不变"可同时出现；单一总状态无法表达。三者是**不同问题**：增长空间 / 兑现把握 / 竞争壁垒。
- **状态变更触发**：仅当有**新信息改变该维度证据**时（由 `claim_impact` 驱动）。
- **"待判断" vs "不变"**：待判断=信息不足、无法判断；不变=已研究且确认无变化。
- **"无新增信息不制造状态变化"程序化**：状态变更函数仅在 `new_info != ∅ AND affects_dimension` 时运行；否则保持原值 + 记录"本次核查无变化"（承 N4.5-05）。

*(第四章的章间接口、冲突清单、最小数据集、T 映射、交接要点见文末统一章节。)*

## 3. 两章接口与冲突清单（第四章视角）

### 3.1 两章接口表（第四章产出 → 第五章使用 → 第七章合成）

| 第四章产出 | 第五章如何使用 | 第七章如何合成 | 关键字段 |
|---|---|---|---|
| `baseline.driver_model` | 估值的**经营假设**来源（增长/利润假设直接引用驱动） | 建议的"价值与价格"字段引用 | `driver → forecast assumption` |
| `baseline.value_state`（动力/确定性/护城河） | 独立判断的**业务证据**基础 | 建议的"变化原因 + 价值"字段 | `value_state` 三字段 |
| `baseline.realization_stage / confidence` | 估值情景（近兑现/远兑现）与敏感性 | 建议的"时点/为何现在" | `timeline`, `confidence` |
| `baseline.valuation`（财务与估值项） | 与反向估值对照，形成独立判断 | 建议的"收益比较" | `valuation` 对象 |
| 第四章 gap（驱动/财务缺口） | 第五章覆盖缺口的一部分 | 建议的"验证与反证/数据缺口" | `gap` 对象 |
| **第五章产出** `gap`（价格隐含 vs 独立判断） | —— | 第七章"待判断"状态的输入 | `gap.type=price_vs_independent` |

**第二章承接核对**：第二章要求"价值层面聚焦增长动力、增长确定性和护城河；价格层面理解外部预期、价格隐含假设和 Agent 独立判断之间的差异"。
→ **第四章完整承接价值层面**（三个维度即动力/确定性/护城河，见 N4.5-02）；
→ **第五章完整承接价格层面**（三份判断即外部预期/价格隐含/独立判断，见第五章 N5.1-03）；
→ **无遗漏、无重叠**：第四章三个维度不涉及价格；第五章三份判断不涉及价值机制。交界处由 `baseline` → 估值假设这一条线连接，唯一重叠点是"独立判断"需要引用第四章价值证据（属正确的依赖，非重复）。

### 3.2 两章共同冲突与张力清单（C45）

| 张力编号 | 涉及原文两方 | 冲突描述 | 裁决建议 |
|---|---|---|---|
| C45-1 | 第五章反向估值（先有价格反解假设） vs 第四/五章"先完成经营假设再计算价值，不倒填参数" | 表面矛盾（一个先价格、一个先假设） | 裁决：**反向估值是"诊断"，正估值是"定价"**。反解不产生建议，只输出"使当前价格成立的假设组合"（诊断当前预期）；定价必须**先有 baseline（经营假设）→ 再算价值**。二者共享假设对象但**方向相反、用途不同**：反解→诊断，正估→结论。程序上：反向估值的输出可作研究线索，但**不可直接作 baseline 输入**。 |
| C45-2 | "不默认编造情景概率" vs "有依据的概率加权结果"（第十一章待定项） | 无据不给概率 vs 允许有据概率 | 裁决：概率字段**可为空**，默认不填；仅当有依据时可填。首版方法待定 → 用显式 `method_status=pending` 表达，**不默默选默认值**。 |
| C45-3 | 第四/五章需模型推理（估值假设、护城河判断） vs 第九章"计算不靠模型口算" | 推理 vs 确定性计算 | 裁决：**模型产出假设与判断（结构化成字段），程序执行全部算术与口径检查**（承 N9.2-03，与 C3 同构）。护城河判断是模型/人工工作，但"证据组合门槛"由规则校验。 |
| C45-4 | "不预设固定分数加权"（第六章） vs 估值中多假设需取舍 | 禁分数 vs 需合成 | 裁决：禁止**固定来源分数加权**；允许**结构化假设组合 + 确定性计算**。多假设合成走模型（模型估计）+ 区间表达，不以"来源分数"合成。 |
| C45-5 | 护城河判断（第四章） vs 股价表现（第五章） | 原文"股价上涨不自动证明护城河增强"，但护城河研究需竞争数据 | 裁决：**硬隔离**——护城河字段的写入源**不含价格数据**；价格波动只能触发"复查"，不能写入护城河结论。竞争数据来自第六章证据，不来自行情。 |
| C45-6 | AGIX 是 ETF（含非上市资产） vs 个股估值方法 | 能否共用一套 baseline | 裁决：**共用 baseline 骨架，但用 `asset_type` 分派**：ETF 的 `non_listed_assets` 与 `holdings_disclosure_lag` 走缺口/敏感性字段，不套用个股的"赚钱机制"链路；收益预测仍用同一期间/情景口径（N5.4-06）。 |
| C45-7 | "待判断"在第五章（价格判断）/第七章（建议）/第二章（卖出边界）三处出现 | 是否同一状态 | 裁决：**同一顶层展示态，底层缺口对象不同**：第五章=价格/预期证据不足；第七章=相对收益无法判断；第二章=卖出规则边界。三者不互相转换（尤其不得由前两者自动升级为"卖出"）。 |

## 6. 给架构师的交接要点（第四章）

1. **赚钱机制要结构化成对象**（payer/offering/conversion_chain/cost/capital/unit_economics），每段挂 evidence；不是散文（N4.1-01）。
2. **指标集按 business_id 路由、可插拔注册**：混合公司分部独立，汇总在分部层完成，防止串味；三类不穷举，预留第四类扩展（N4.1-10）。
3. **三态驱动 + 置信度分离 + 3×4 状态**：realization_stage、timeline、confidence 独立；状态三字段独立、"待判断≠不变"、无新信息不变化（N4.2-01/03、N4.5-02/03/05）。
4. **护城河反误判规则可执行**：单点证据（领先/紧缺/高毛利）不足以定长期护城河；六保护对象多选 + 四类来源区分；**护城河字段写入源不含价格数据**（N4.3-06/07、C45-5）。
5. **反形式主义 + 缺口对象**：程序做形式完备性检查（非空/定位/推导/一致），人工做实质评审；gap 与 N9.1-21 复用（N4.4-02/04）。
6. **增量更新直接复用 N9.1-33 追加式不可变 + 双时间轴**，不新建机制（N4.5-01）。
